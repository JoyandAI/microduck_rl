## 0. TL;DR

1. **可行，但必须"重标定执行器模型 + 更新机器人质量 + 重训"，不是改一行配置。**
   策略网络结构、61 维观测、14 维动作、ONNX 契约都不变。
2. **扭矩基本相当、速度腰斩**：HL-2909-C001 堵转 8.9 kg·cm（0.873 N·m）@12V，与 XL330
   在现 sim 电压下的 ~0.85–1.07 N·m 相当（略小）；但空载速度 77 rpm（8.06 rad/s）
   只有 XL330 的一半左右（~150 rpm @7.4V）。**最大步频/步速上限会明显下降。**
3. **最大的 sim2real 风险不是参数，而是控制律**：飞特固件自带"目标速度/加速度
   限幅（缓起缓停）"，而现在的 XL330 BAM 模型没有这一项。不在 sim 里建模，
   训练出的策略在真机上必然滞后、抖振。
4. **建议 v1 用位置伺服模式（Mode 0）**，保持"策略 50 Hz 下发位置目标、
   舵机内部闭环"的现有架构；恒流/恒力模式（Mode 2 + 地址 44）是力矩控制路线，
   需要换 `CurrentControlledActuator` 类 + 改运行时，改动量大，不建议第一步做。
   注意：官方内存表确认固件有**完整的 P-D-I 位置环**（EPROM 21/22/23 → SRAM
   50/51/52，0–254，**Kp 1/8 缩放、Kd 1/4 缩放**），而 BAM 的电压控制类是
   "P-only + 反电动势"——sim 侧要显式建模 D 项（或用等效阻尼折算），且
   运行时写入的增益必须与 sim 一致。
5. 好消息：重量接近（27.8 g vs 18 g，14 个合计 +137 g ≈ +18.6%）、分辨率相同
   （4096）、回差规格相同（≤1°，与仓库 -Backlash- 变体的 ±1° 假设一致）。

### 1.1 固件内存表（官方文档权威版，已存档 `docs/feetech_hls_memtable.md`）

> 来源：飞特官网文档站《磁编码HLS舵机-内存表解析》
> （code: FT-HLS-emanual，该文档为 HL-2909 同一固件族 FT-HLS 的内存表）。
> 协议：**FT-SCS 自定义协议**，默认 1 Mbps / 8 数据位 / 无校验 / 1 停止位 / 默认站号 1；
> 多字节数据低位在前。

| 地址(DEC) | 功能 | 字节 | 范围 / 单位 | 关键说明 |
|---|---|---|---|---|
| 5 / 6 | 主 ID / 波特率 | 1 | 0–253 / 0–7（0=1 M…7=38.4 k） | 默认 ID=1、波特率=1 M |
| 9 / 11 | 最小/最大角度限制 | 2 | 0–4094 / 1–4095（0.087°） | 多圈时置 0 |
| 16 | 最大扭矩 | 2 | 0–1000（0.1%） | 默认 980（98%），上电赋给 48 |
| **21/22/23** | **位置环 P / D / I 系数** | 1 | 0–254 | **EPROM 参数，上电赋给 50/51/52**（HLS 有完整 PID！） |
| 26 / 27 | 正/负向不灵敏区 | 1 | 0–16（0.087°） | 默认 1 |
| 30 | 角度分辨率 | 1 | 1–128 | 传感器分辨率放大系数（出厂=1，别动） |
| 31 / 32 | 位置偏移 | 2 | ±4095（0.087°） | 中位校准 |
| **33** | **运行模式** | 1 | 0–3 | 0=位置伺服（位置+限流）/ 1=恒速+限流 / 2=**恒流（恒力）** / 3=PWM 开环 |
| **40** | 扭矩开关 | 1 | 0–2 | 0=关 / 1=开 / **2=阻尼输出** |
| **41** | 加速度 | 1 | 0–254（8.7°/s²/LSB） | **0=最大加速度**（缓起缓停参数，必须建模） |
| 42 / 43 | 目标位置 | 2 | ±32767（0.087°），BIT15=方向 | 绝对位置，±7 圈多圈 |
| **44 / 45** | **目标电流** | 2 | ±2047（**6.5 mA/LSB**） | 位置/恒速模式=**电流上限**；恒流模式（2）=目标电流=**恒力输出**，BIT15=方向 |
| 46 / 47 | 运行速度 | 2 | ±32767（**0.732 RPM/LSB**），0=停止 | 默认=出厂最大速度 |
| **48 / 49** | **转矩限制** | 2 | 0–1000（0.1%） | 程序可改的堵转扭矩上限（默认 980=98%） |
| **50/51/52** | **Kp / Kd / Ki** | 1 | 0–254 | 位置环：Kp 比例系数（**注释 1/8 缩放**）、Kd 微分系数（**1/4 缩放**）；Ki 位置模式无效 |
| 56–70 | 当前位置/速度/负载/电压/温度/电流 | 2/1 | 反馈 | 负载=电压占空比（0.1%，BIT10 方向） |
| **77–86** | **出厂参数（只读）** | 1 | vFk/vKgI/pFk(*10)/移动速度阀值/**DTs(ms)**/eFk(*10)/Vk(ms)/**最大速度限制**/**加速度限制**/**加速度倍数** | **是厂商标定的电机/固件参数，BAM 标定的现成锚点**（含控制周期 DTs、反电动势系数 eFk） |

**对建模的直接影响**（替换早前基于开源 SDK 的推测，以下为官方确认）：

1. **固件位置伺服 = 加速度爬坡（41，0=最大）→ 速度上限（46）→ 位置环 P**（50）**+D**（51）
   → **电流限制（44）/ 转矩限制（48）→ 电机**。BAM 的 STS3215 参考类只做了
   **速度**限幅（`q_target_smooth`），HL-2909 还要加**加速度**限幅（二阶爬坡），
   否则低速大转角指令（站起时 ±1 rad 的腿摆）在 sim 里响应比真机快。
2. **HLS 固件有完整 P/D/I（可调）**——不是早前从开源 SDK 推断的"固定 PID"。
   且 **Kp 带 1/8 缩放、Kd 带 1/4 缩放**（官方说明），BAM 现有 `kp_fw` 是
   "P-only + 反电动势"，**D 项需要在执行器类里显式建模或折算成等效阻尼**。
3. **地址 44 是"目标电流"**（6.5 mA/LSB）：位置模式下是**电流上限**（电机恒力
   的机制=限流），恒流模式（2）下才是恒力输出——分析文档此前写的"恒力=地址44"
   与"力矩单位%"两个推测据此修正。
4. **ACC=0 = 最大加速度**（非"无限制"）；且出厂参数区（85/86）给出了固件的
   最大加速度限制与倍数——sim 的 `max_acceleration` 直接读这两个只读寄存器。

**读表结论**：HL-2909-C001 不是"更强/更快"的升级，而是"同扭矩、半速度、同精度"的替换。
机器人整体能力边界会收缩在速度上；扭矩刚好够（0.87 N·m vs 当前 ~0.85–1.07 N·m），
高扭矩任务（roulade、带 38% 质量的头的站起）要先在 sim 里验证可达性，
不行就启用后备方案（14 kg 空心杯款：1.39 N·m，110 rpm，27.8 g）。

## 2. 对 RL 链路的影响总览

```
训练闭环（本仓库）                      真机（另一个仓库）
┌────────────────────────────┐
│ MJCF 机器人模型（质量/惯量） │   ← 舵机质量/尺寸变化 → 更新
│ BAM 执行器（电压控制律+摩擦）│   ← 舵机电机/固件参数变化 → 重标定
│ DR（电压/延迟/摩擦/编码器）  │   ← 供电/总线/回差变化 → 重新标定
│ 奖励/指令范围/课程表         │   ← 速度上限变化 → 重调
│ PPO 策略（61D obs/14D act） │   ← 必须重训（不能沿用旧权重）
└────────────────────────────┘
```

不变的部分：观测布局 61D、动作 14 维位置目标、ONNX 导出/烘焙归一化、
`infer_policy.py` 演练、任务注册结构、-Backlash- 变体机制。
**旧策略 checkpoint 在真机上"能加载但动力学错位"，必须全部重训。**

## 3. 逐文件改动清单

### 3.1 BAM 包（git 源依赖，需 fork 或向 Rhoban/bam 提 PR）

bam 通过两层注册把"舵机型号"变成可用的执行器（已核对 `.venv` 中安装的
bam 1.0.1 / mjlab_frictionloss 分支源码）：

1. **参数文件** `bam/params/<motor>/mX.json`：由 `bam.fit`（测试台标定）产出，
   包含 `kt / R / armature / q_offset / friction_base / friction_stribeck /
   load_friction_* / dtheta_stribeck / alpha / friction_viscous / model / actuator`。
   - 现有参考：`bam/params/xl330/m6.json`（kt=0.366, R=2.81, armature=0.00181…）
     和 `bam/params/feetech_sts3215_7_4V/m1.json`（kt=1.212, R=2.68, armature=0.0284…）。
   - HL-2909-C001 的**标定锚点**（数据手册可交叉验证拟合结果）：
     - kt ≈ 1.454 N·m/A（官网 KT=14.83 kg·cm/A，输出端）；
     - R ≈ 20 Ω（12 V / 0.6 A 堵转电流的等效值，以实测为准）；
     - 堵转扭矩 ≈ 0.873 N·m；堵转电流 0.6 A；空载电流 140 mA。
2. **执行器类**（新 `bam/feetech/hls.py` 之类，或直接扩展 `bam/feetech/actuator.py`）：
   参照现成的 `STS3215Actuator`（`bam/feetech/actuator.py`）：
   - `vin=12`，`kp`/`error_gain`/`max_pwm` 需示波器实测
     （STS3215 参考值：kp=32, error_gain=0.166, max_pwm=0.97）；
   - **`compute_control` 里实现固件目标"速度+加速度"双限幅**：内部目标按
     `max_velocity` 和 `max_acceleration` 二阶爬坡 —— 本次换舵机在 sim 侧
     **必须新增**的行为。两个值的来源（官方内存表已确认）：
     - `max_acceleration`：寄存器 41 的语义是 0=最大加速度（8.7°/s²/LSB），
       固件最大加速度限制在**出厂参数 85/86**（加速度限制 × 加速度倍数）——
       sim 直接使用运行时"ACC 写 0"时的实际爬坡（= 出厂限制值，实测可得）；
     - `max_velocity`：出厂参数 84（最大速度限制）；运行时 SPEED 写 32767 时
       实际达到 ≈ 84 的值，实测确认。
   - **固件是 P-D-I 位置环（可调，EPROM 21/22/23 → SRAM 50/51/52），且 Kp 有
     1/8 缩放、Kd 有 1/4 缩放**（官方说明）：BAM 的 `VoltageControlledActuator`
     是 "P-only + 反电动势"，**需要在 HLS 类里显式建模 D 项**（或把 D 折算进
     等效阻尼 —— 两者都要先过测试台阶跃对比验证），I 项在位置模式下无效可忽略。
   - 电流/转矩限制（44 / 48）在位置模式下只是"上限"，BAM 的 `max_pwm` /
     `forcerange` 承担等效角色；恒力输出需要模式 2 + 44，留作后续。
3. **注册** `bam/actuators.py`：加 `"hls2909": lambda: HLS2909Actuator(Pendulum)`，
   与 `"sts3215"` 并列；`bam/mjlab.py` 的 `motor_name` 支持列表随之可用。
   （不需要改 mjlab.py 本身——它是按 JSON 的 `"actuator"` 字段查注册表的。）
   14 个全换已确认 → `microduck_constants.py` 里单套 `actuators = FrictionDRBamActuatorCfg(...)`
   即可，无需混合配置。

### 3.2 `src/mjlab_microduck/robot/microduck_constants.py`（本仓库核心改动点）

`_BAM_ACTUATOR_KWARGS`（约第 120–132 行）：

```python
_BAM_ACTUATOR_KWARGS = dict(
    motor_name="xl330",          # → "hls2909"（或 json_path 指向标定文件）
    model="m6",                  # → 标定产出对应的模型阶数（建议先 m1/m2 起）
    kp_fw=200.0,                 # → 标定值（Dynamixel 增益刻度 ≠ 飞特 0-254 刻度，不能沿用 200）
    vin_range=(6.5, 8.2),        # → 按整机供电实测，例如 (10.5, 12.6)
    vin_drop_gain_range=(0.0, 0.2),  # → 重新标定（电压跌落模型）
    vin_min=6.0,                 # → 例如 10.0
    delay_min_lag=3,             # → 重新实测（半双工 TTL 1 Mbps、14 舵机轮询时序）
    delay_max_lag=6,             # → 同上
)
```

注意 `edit_spec` 里 `forcerange = ±(vin·kt/R)`：**电压和 kt/R 不改，sim 里的
力矩上限就是错的**（BAM 用 `vin_range` 上界算力限）。

### 3.3 机器人模型（`robot/microduck/robot_*.xml` 或重导出）

- 每个舵机本体质量 18 → 27.8 g、尺寸 20×34×26 → 34×20×23 mm：
  最优是 Onshape 里换舵机 CAD 后重跑 onshape-to-robot 导出；
  否则手工改相关 body 的 `<inertial mass=... fullinertia=...>`。
  合计 +137 g（+18.6%），CoM/惯量变化不大但**必须更新**——尤其头/颈（占 38% 质量）。
- 关节限位与 HOME_FRAME：只要机械安装位不变就不动；
  新舵机 360° 无机械限位 + ±7 圈多圈模式，不会引入新的软件限制。
- 回差：实测 HL-2909-C001 输出轴回差，若 ≈±1° 则 -Backlash- 变体原样可用；
  若偏差大，改 `add_backlash.py` 的角度并重导出 3 个 backlash XML。

### 3.4 任务配置（`tasks/microduck_velocity_env_cfg.py`，以及各任务家族）

- **指令范围**（先 sim 测可达速度，再定数字，别拍脑袋）：
  - `lin_vel_x ±0.4` → 预计降到 **±0.15~0.25** m/s；`ang_vel_z ±1.0` → 预计 **±0.5** 左右；
  - 侧向 ±0.3 → 相应下调。
- **步态奖励**：`air_time` 窗口 `[0.125, 0.300]` s 在慢舵机下可能要放宽
  （步频上不去）；`foot_swing_height`/`foot_clearance` 的 2 cm 目标先确认
  在 8 rad/s 下能否达到（摆动相时间变长 → 物理上仍可达，但要重看）。
- **头部指令**：4 个头部关节同样变慢，`head_pose` 的 ±1.1 rad 指令 + 50 Hz 下发
  在固件限速下会明显滞后——可能要缩小范围或拉长 `HEAD_POSE_CMD_RESAMPLE_S`；
  `head_pose_bias` 惩罚（EMA 直流偏置）保留。
- **课程表**：速度变慢后，各 stage 的步数节奏（如 `500×24`）可能要拉长；
  遵循 AGENTS.md 的原则：阶段推进以策略实际学到的东西为准。
- **DR 范围**：`JOINT_FRICTION_RANDOMIZATION_RANGE`、`ARMATURE_*` 按标定结果
  重设（HL-2909 减速比 320:1、铁芯电机，摩擦/惯量与 XL330 不同）；
  `ENCODER_BIAS_RANGE` 可保留（分辨率相同）；
  kp/kd 随机化保持默认关闭即可。
- 各任务家族的 cfg（standup/roulade/ballkick…）沿用 velocity 的改动思路，
  高扭矩任务先做可行性验证（见 §6 风险 4）。

### 3.5 运行时（`pollen-robotics/microduck` 仓库，不在本仓库）

- 协议：Dynamixel 2.0 → **FT-SCS 自定义协议**（默认 1 Mbps / 8N1，站号 1，ID 0–253，半双工 TTL）。
- **必须显式写固件寄存器，且与 sim 建模值一致**（地址见 §1.1，官方内存表已确认）：
  - `MODE=33` 写 0（位置伺服）；`TORQUE_ENABLE=40` 写 1；
  - `ACC=41` 写 **0（=最大加速度）**；`GOAL_SPEED=46/47` 写 32767（最大，实际
    受出厂参数 84 限制）——**写成 sim 里建模的那组值**；
  - `Kp/Kd/Ki=50/51/52`：写成与 sim 一致的位置环增益（注意 Kp 是 1/8 缩放、
    Kd 是 1/4 缩放，换算时按固件单位写）；EPROM 21/22/23 同理（掉电保存）；
  - `TORQUE_LIMIT=48/49`：转矩上限（默认 980=98%），与 BAM `forcerange` 对齐；
  - `GOAL_POSITION=42/43` 每步写目标位置（50 Hz，同步写/异步写均可）；
  - 每舵机 ID（5）与波特率（6）事先配置并 `LOCK=55` 写 1；`ANGLE_LIMIT=9/11` 设
    成机械限位（多圈模式下按需置 0）。
- 供电 12 V（9–14 V 范围）；电流保护按 0.6 A 堵转设计。
- 恒力/恒流路线（模式 2 + `GOAL_CURRENT=44/45`）留作后续力矩控制（此时 44 是
  目标电流 6.5 mA/LSB；位置模式下 44 只是电流上限）。
- 观测 61D 契约不变 → 策略热插拔机制不动。

## 4. 必须实测/标定的清单（内存表给不了的部分）

> 内存表已解决：ACC=0=最大加速度、PID 可调（P/D/I，0–254，Kp 1/8 缩放、Kd 1/4）、
> 44=目标电流（6.5 mA/LSB；位置模式=限流、模式 2=恒力）、48=转矩限制（0.1%）。
> 剩下的都需要物理测量：

1. **BAM 测试台标定**（走仓库现有流程：`scripts/testbench_sim2real.py`、
   `scripts/validate_bam_testbench.py`，摆锤 + 阶跃实验）：`kt`、`R`、`armature`、
   摩擦预算各分量、`q_offset`。**锚点①**：出厂参数区 77–86（只读，含
   DTs 控制周期、eFk 反电动势系数、最大速度限制 84、加速度限制 85/86）
   读出来直接对照拟合结果。
2. **示波器测固件占空比**：`kp`、`error_gain`、`max_pwm`（BAM 对 STS3215 就是这么干的；
   这一步同时解决"Kp 1/8 缩放"在电压模型里的真实映射——固件 kp=40 时占空比到底多大）。
3. **阶跃响应曲线**：60° / 120° 阶跃（ACC=0、SPEED=32767、不同 Kp/Kd 组合），
   验证 sim 的"加速度+速度双限幅 + P-D 位置环"与真机时间曲线重合。
4. **总线延迟**：指令下发 → 全部 14 个舵机反馈读回的整链路时延（定 `delay_*_lag`）。
5. **回差实测**：正反转滞回（定 -Backlash- 角度；官网标称 ≤1°，死区寄存器默认 1）。
6. **编码器噪声/零偏**：定 `ENCODER_BIAS_RANGE` 和 obs 噪声。
7. **整机供电**：电池/BEC 实际电压范围（定 `vin_range` / `vin_min`）。

## 5. 建议实施顺序

1. **标定先行**（1–2 周，可与第 2 步并行）：测试台标定 + 示波器 → 产出
   `bam/params/hls2909/mX.json` 与 `HLS2909Actuator`（含目标速度+加速度双限幅）。
2. **模型更新**：MJCF 质量/几何 + `microduck_constants.py` 参数接入。
3. **sim 可行性验证（训练前必做）**：目标姿态 settle 测试；扫描最大可达
   速度/步频（决定指令范围）；roulade/standup 等任务先跑
   `scripts/validate_bam_testbench.py` 风格的对照，确认扭矩够用。
4. **冒烟 → 重训**：先 64 envs / 5 iters，再按预算跑（走姿 4000–6000 iters）。
5. **导出 → 演练 → 真机对照**：`scripts/export.py` → `scripts/infer_policy.py`
   → sim2real 对比（速度曲线、关节轨迹、回差），迭代 DR/延迟。
6. （可选后续）恒力/恒流模式路线：换 `CurrentControlledActuator`
   （类似 bam 的 `xl330i`）、动作从位置目标改为力矩目标、运行时改为力矩流，
   这是另一个量级的改动，建议 v1 先不做。

## 6. 风险与坑（按重要性排序）

1. **固件缓起缓停（ACC+SPEED 双限幅）不建模**：sim 里策略可以"瞬移"目标，
   真机做不到 → 部署后全身滞后/抖振。这是本次换舵机第一大坑。
2. **指令范围不降**：±0.4 m/s 对半速舵机不可达 → 策略学出原地踏步或暴力抖腿
   （AGENTS.md：速度类指令超出物理能力时训练会退化）。
3. **kp_fw / error_gain 沿用 XL330 的**：位置误差 → 电压的映射全错，
   等效刚度错好几倍，行为完全不对。
4. **扭矩余量**：HL-2909 堵转 0.873 N·m 且额定仅 0.284 N·m —— roulade、
   stand-up（头重 38%）等高峰值力矩任务先验证；不行换 14 kg 空心杯后备款。
5. **电压忘记改**：`vin_range` 还是 6.5–8.2 的话，BAM 的
   `forcerange = vin·kt/R` 会把力矩上限算成新舵机实际值的一半不到。
6. **质量不更新**：CoM/惯量错位，尤其是头部（38% 质量）的动力学。
7. **运行时寄存器不一致**：真机 ACC=0/SPEED=32767/Kp/Kd/转矩限制 48 与 sim
   假设不一致，等于部署了一台"另一个机器人"（寄存器地址与单位见 §1.1/§3.5）。
8. **总线延迟变化**：半双工轮询 14 个舵机 + 12 V 电源噪声，
   延迟 DR 的 3–6 步（60–120 ms）窗口要实测重定。

## 7. 一句话总结

换 HL-2909-C001 在 RL 侧 = **给 bam 加一个"带固件目标速度+加速度限幅的 12 V
飞特执行器"、重标定其电机/摩擦参数、更新机器人质量和电压 DR、下调速度类指令范围、
然后全量重训**；架构（61D obs / 14D 位置动作 / ONNX 契约）不动，但任何
"只换型号不改模型"的捷径都会在真机上原样暴露。
