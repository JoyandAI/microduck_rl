## 1. 评测口径（不读这段会误读所有数字）

| 量 | 协议 | 说明 |
|---|---|---|
| **走动 / 速度 / 摔 / 窗口** | 64 env × 20 s，**冻结 vx=0.2 m/s**，DR 全开，seed 0 | "走动环境" = `speed_along > 0.02 m/s`；速度是世界系净前进速度 |
| **flight（跑步相）** | 64 env × 20 s，agent D 验证过的探针 | 双脚同时离地的时间占比。官方 = 0.000 |
| **站立 reset / 倾角 / 离地** | 单环境 × 20 s，**零命令**（部署待机态） | `gait_forensics`；离地间隙：仓库档位 **站立 0.5–4.2 mm、踏步 19.4 mm**，判定线 8 mm |
| **净转角** | 20 s 内累计航向变化的中位数 | 越低越直；官方（它自己的模型+舵机）= **4.5°** |
| **°/m** | 走动环境的净转角 ÷ (速度 × 20 s) | 把"慢"和"直"分开；官方 = 11.1°/m |
| **<30°%** | 20 s 内净转角 <30° 的环境占比 | 分布指标，防止中位数掩盖双峰 |

**三条必须遵守的口径纪律**（都是踩过坑的）：
1. **跨物理比较不成立**：官方策略只在它自己的模型+舵机（`preswap`+`xl330`）上成立；放到我们的
   m5 HD-1910 物理上它 **45/64 环境会摔**。所以官方数字只作参照系，不作对比基线。
2. **跨日期的 JSON 不能直接排名**：同一个 ONNX 两次评估能差 ~10°（评估器/日期漂移）。本文所有
   同表数字来自同批次评估。
3. **训练期指标不能代替评测**：`Episode_Reward/<项>` 是**加权**值，且像 `flight` 这种累计量会被
   "走了多久"污染（`ours_flight_s42` 训练期 flight 惩罚最大，探针测出它的飞行相最少）。

## 4. 每个"改动方向"的实测效果

### 4.1 ✅ 换配方族：12 偏差 → 官方默认 + 头块（**效果最大**）

同 seed 42、同观测/命令/推力/头块/舵机：

| | 12 偏差族（`ours_flight_s42`） | 官方默认族（`famB_head_flight s42`） |
|---|---|---|
| 走动环境 | 35/64 | **60/64** |
| 速度 | 0.026 m/s | **0.117 m/s**（4.5×） |
| 净转角 | 160.8° | **57.7°**（2.8×） |
| °/m | 205 | **21.5** |

### 4.2 ✅ 加 flight 惩罚

- flight：`align_fwd` 0.236 / `ck7000` 0.120 / `ours_head` 0.229 → **0.017–0.043**（官方 0.000）
- 站立：62–64 次摔 → **1 次**；离地 17–69 mm → **0.3–0.9 mm**（6 个 run 一致）
- 漂移 DC：22.9 → 5.6 deg/s

### 4.3 ✅ 加预算到 12000 it + **选用中途 checkpoint**

- 预算 9000 → 12000：famB 用的就是 12k（官方 runner cfg 是 50000）。
- 中途点普遍更好（§2.2），退化最高 5.7× —— 这是**不花 GPU 小时**的提升。

### 4.4 ⚠️ 零命令训练（治踏步）——**famB 唯一没达标的一项，已合并进统一模型**

用户指出：`famB_head_flight s42` **会原地踏步**。确认：零命令下检测到 **2.15 Hz 步态节奏**、
脚抬 **14.65 mm**（判定线 8 mm）。不摔（64 env 0 reset、倾角 5.6°），但确实在踏步。

**根因**：零命令下 `track_linear/angular_velocity` 只要求"身体不移动"，而**原地抬脚并不违反它** ——
踏步在官方配方里完全没有价格。官方配方也没有 `POSE_ZERO_CMD_PROB` 桶和零命令项。
同速度对照（都 ~0.115 m/s）：12 偏差 + flight 的 `ours_flight_s42_r2` 站立离地 **0.34 mm**（不踏步），
差别正是这三项：
- `stillness_zero_cmd`（对运动单调递减，无阈值可卡）
- `no_stepping`（直接罚抬脚，docstring: *"Discourages marching in place when the robot should stand still"*）
- `yaw_hold_zero_cmd`（站定时按住朝向）

→ 新增窄开关 `MICRODUCK_ZERO_CMD_TERMS=1`，**只**注册这三项 + 它们的爬坡课程；三项都按
`cmd_speed < 0.01` 门控 ⇒ **走路时恒为 0，对步态零影响**（构造保证）。4 个测试锁住：
默认关闭与官方逐项等价、打开只多这三项（整份 cfg 快照 diff）、三项都被零命令门控、权重一致。

### 4.5 ❌ 已证伪的方向（不要再走）

| 方向 | 实测结果 |
|---|---|
| `turn_first`（转向优先课程） | 转向增益 1.9–5.7%（官方 57.6%），有两对符号反 → 失败 |
| `yaw_z_track`（去稀释偏航率跟踪） | 234.3°，无改善 |
| `yaw_dc` 单独用 | 直行改善到 154.4°（12 偏差族最好），但站立 **56 次摔 / 63 mm**、flight 0.275（最差） |
| `feet_max_width` 单独用 | 站立 85.86 mm 乱蹬（比不加更差），直行 213.1° |
| `hip_roll` 收紧 pose std / L1 | 零命令存活 100% → 0%，终态倾角 47° |
| 命令速度上限 0.15 m/s | **未验证**（相变假设：0.10→0.20 m/s 之间每步冲量 ×93），且会降速，故不合并 |

## 6. 两个必须记住的坑（这两天踩的）

1. **队列脚本的 run 目录解析**：`MICRODUCK_TASK_NAMED_RUNS=1` 遇到重名会把新 run 静默改名成
   `<name>_r2`，而旧脚本先看"约定路径是否存在"→ 导出了**上一次训练**的 checkpoint。
   已用 ONNX 权重比对证明（`max|Δ| = 0.000e+00`）。已修：以训练日志为准 + checkpoint 必须晚于本臂开始时间。
   影响：`queue_overnight` 的 3 个 flight 臂的 ONNX/评估其实是 routeA 的，r2 三次训练从未被评估
   （后来由 checkpoint sweep 补上）。
2. **零命令评估是假阴性**：`eval_straightness.py` 把 `len(t) < 20`（0.4 s）的环境记为
   `insufficient_data` 丢掉，而"站定就摔"正好表现为立刻 reset → 全部 64 个环境被丢掉、
   看起来像"没数据"。这就是 62–64 次摔的塌陷两天没被发现的原因。现在每个臂都跑真正的
   `gait_forensics` 站立探针。
