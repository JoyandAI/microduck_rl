## 4. 改了什么

### 4.1 默认配方整体退回官方（9 处偏差全部变成 opt-in）

| 偏差 | 旧默认 | **新默认（= 官方）** | 恢复开关 |
|---|---|---|---|
| 姿态卫生 7 项（`stance_hip_yaw` / `action_over_limit` / `neck_motion` / `standing_leg_vel` / `stillness_zero_cmd` / `no_stepping` / `yaw_hold_zero_cmd`） | 开 | **关**（且**不再注册**这三个零权重死项） | `MICRODUCK_STANCE_HYGIENE=1` |
| `pose` 归约器 | `per_joint_posture` | **`variable_posture`**（mjlab 原式） | `MICRODUCK_PER_JOINT_POSTURE=1` |
| `air_time` | progress-gated | **stock `feet_air_time`** | `MICRODUCK_AIR_TIME_GATE=1` |
| `heading_hold`（偏航角项） | 开（权重 2.5） | **关** | `MICRODUCK_HEADING_HOLD=1` |
| `hip_roll` 的 pose std | 0.12 | **0.05** | `MICRODUCK_HIP_ROLL_STD=0.12` |
| head/body 命令零桶 | 0.1 | **0.0** | `MICRODUCK_POSE_ZERO_CMD_PROB=0.1` |
| `abduction` / `yaw_dc` / `turn_first` / 镜像损失 | 关 | 关（不变） | 各自开关 |

**为什么是"退回去"而不是"再调一调"**：这 9 处每一处都是为了补**上一个策略**的症状而加的，
而它们的验证方式都是**比较两次独立训练** —— 而本仓库已实测这种比较**分不开任何一臂**
（臂内 seed SD > 臂间差；见上表 D vs A）。其中至少两处被实测证明**更糟**
（`hip_roll` std 收紧：外八 0.454 → 0.583；`hip_roll` L1：站立存活 100% → 0%）。

### 4.2 唯一保留的例外（除 BAM/舵机）

**BAM + 舵机参数**（`robot/microduck_constants.py`：HD-1910-C001、`kp_fw=32`、7.5 V、m5、
lag 4..7）**完全不动** —— 这是用户明确划出的例外，也由 `test_official_alignment.py`
单独断言（`KP_FW == 32.0`、`motor_name == "hd1910"`、`vin_range == (7.1, 7.9)`…）。

**头部稳定性层**（用户要求，默认开，`MICRODUCK_HEAD_STABILITY=0` 可关）：

| 项 | 函数 | 权重 | 标定依据（实测） |
|---|---|---|---|
| `head_motion`（头乱动） | `neck_joint_vel_deadband_l2`，deadband **2.0 rad/s** | **−0.08** | 官方步态颈部步频幅度 0.75° @2.15 Hz ⇒ 峰值 ≈0.18 rad/s ⇒ **免费**；坏策略 16.4° ⇒ ≈3.87 rad/s ⇒ 计费。deadband 卡在两者之间 |
| `head_droop`（低头） | `mdp.head_droop_penalty`，**单侧**、**相对命令**的 pitch L1，deadband **0.15 rad** | **+2.0**（函数返回 ≤0） | 坏策略 `neck_pitch` 停在 −1.934（离 HOME），官方 −0.127。−1.934 处扣 (1.934−0.15)×2.0 ≈ **−3.57/步**；官方姿态付 0 |

两项都走与官方 `head_pose_bias` **同一条时间线**（600 迭代前 0，1500 到满权），
因为 AGENTS.md 的规矩是"技能还在摸索时上税会让什么都不做成为最优解"。

**为什么"低头"要用单侧、相对命令的项**（而不是再收紧已有项）：

* `head_pose_tracking`（官方，2.0）是 4 个关节的**高斯均值**，一个关节停死只掉 1.0→0.667，
  在 1.93 rad 误差处梯度 **−9.8e-6 /rad** —— 等于不存在；
* `head_pose_bias`（官方，爬到 3.0）形状对，但罚 `|err|`，**把"抬头"也一起罚**；
* 无条件把脖子拉回 HOME 的 L1 会**和 head_pose 命令打架**（这正是 `pose` 奖励排除头颈的原因）；
* ⇒ 只罚 `relu(cmd − actual − deadband)`：**命令要求低头时免费**，**别推就免费**，只有
  "该抬头却垂着"收费。梯度方向恒定、不可刷（抬头方向付 0）。

**符号方向不是猜的**：`tests/test_head_stability.py` 用**真实 MJCF 做正运动学** ——
`neck_pitch = −1.585`（真机/策略停的位置）时头体高度 **156.6 mm**，
HOME（+0.3491）时 **232.6 mm**（= 文档里的标称值）⇒ 负方向确实就是"低头"。

### 4.3 关于"头的重量增加了" —— 实测事实需要更正

从 MJCF 直接读（`robot_walk.xml`）：

| | preswap（官方 XL330 时代） | 现在（HD-1910） | Δ |
|---|---:|---:|---:|
| 头部组件（neck + neck_pitch + yaw_roll_motion + jaw_soft） | 279.93 g | **288.93 g** | **+9.00 g（+3.2%）** |
| 整机 | 737.24 g | 779.24 g | +42.00 g = **14 舵机 × 3 g** |
| 头占整机 | 38.0% | **37.1%** | **下降** |

⇒ **"头变重了"在模型里只成立 +9 g，而且占比反而降低了**；42 g 的增重来自**每一个**舵机。
**但"头很重"这个理由本身是成立的、而且更强**：289 g 挂在 75.6 mm 力臂上 = 整机 37%，
迈步时它**必然**摆动（把脖子动作冻死能消掉 20° 的头摆，躯干倾角却从 2.6° 涨到 5.9° ——
策略在拿头当配重）。所以惩罚的**理由要写成"头占整机 37%、力臂 75 mm"**，
而不是"这次换舵机把头加重了"。

> ⚠️ 仍未解决的一条：模型总重 **779.2 g** vs `AGENTS.md`/官方文档的 **874 g**（差 ~95 g = 12%）。
> 这是**唯一能造成"仿真正常、真机系统性下垂"的确定性偏差**，需要**上秤**确认（§6.3）。

| 零命令离地高度 | **0.00 mm** | 0.23（ck7000）/ 0.15（ck12000） | **< 8 mm** | ③**静止不踏步** |

## 6. 下一步（按"信息量 / 成本"排序）

### 6.1 ⭐ 唯一能结束猜测的臂：对齐后的配方 + 今天的物理

```bash
# 默认已经是"官方配方 + 我们的 BAM/舵机"，直接训即可
uv run train Mjlab-Velocity-Flat-MicroDuck --env.scene.num-envs 4096
```

* 若**走直、不外八、站得住** ⇒ 结论是那 9 处偏差造成的，对齐即完成；
* 若**仍然走歪** ⇒ 在**今天的物理**上，官方配方本身就不够用，
  下一步才有理由开 `MICRODUCK_YAW_DC=1` / `MICRODUCK_TURN_FIRST=1`
  （这两条**从未被证伪，只是被中止**）。

**注意**：`Mjlab-Velocity-Flat-MicroDuck-OfficialRecipe` 那个任务保留着，但现在是
**同义词**（同时它的 `mdp` 符号与官方逐字一致，适合做溯源对照）。

### 6.2 头稳定性 A/B（一臂）

```bash
MICRODUCK_HEAD_STABILITY=0 uv run train Mjlab-Velocity-Flat-MicroDuck --env.scene.num-envs 4096
```
判据就是 §5 的头部三行。**这两项是官方没有的增项，必须能被单独归因。**

### 6.3 需要硬件侧配合的三条（会持续制造麻烦）

1. **上秤**：真机总重（779 vs 874 g）。若 ≠ 779 g ⇒ 改 MJCF 质量并重训。
2. **读真机母线电压 + 固件寄存器**（kp/kd/ki、reg81、reg15）—— 确认真的是 7.5 V / kp=32。
3. **部署侧低通**：`robotd.toml` 的 `head_lowpass=0.5 / legs_lowpass=0.7`
   在训练里**不存在**（`grep ACTION_LOW_PASS src/` 无结果）。实测近似无害（−4.7% 速度、不摔）
   ⇒ **建议在部署侧关掉**，不要为它重训。`action_scale` 已于 2026-09-17 改成显式 **1.0**（训练值）。

### 6.4 不要再做的（已实测证伪）

| 不要再试 | 实测结果 |
|---|---|
| `hip_roll` pose std 收紧到 0.05（**作为"修外八"的手段**） | 外八 0.454 → **0.583（更糟）** |
| 任何形式的**单关节** `hip_roll` L1 | 站立存活 **100% → 0%**、tilt 2° → 47° |
| `MICRODUCK_HEAD_L1=1`（sitstand） | 脖子 −1.934 没动，坐下 **0/8** |
| `head_ground` / `neck_limit_proximity` | 承重修好，脖子不动，坐下退化 |
| 靠"加大刚度"修走歪 | yaw −2.15 → −2.86 → **+2.29** → +5.05（符号乱跳），速度 −83% |
| 用镜像损失当可靠杠杆 | ck2000–5000 的偏航效果**符号翻转** |
