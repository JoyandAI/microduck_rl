## 1. ⭐ 已经实现好、但从没跑过的两个东西（零实现成本）

盘点 `MICRODUCK_*` 开关时发现的。**这两条应该最先跑，因为它们不需要写任何代码。**

### 1.1 `Mjlab-Velocity-Flat-MicroDuck-OfficialRecipe` —— 官方配方 + 我们的硬件

`src/mjlab_microduck/tasks/__init__.py:103` 已经注册了这个任务，注释写得就是这件事：

> *"A/B control: the OFFICIAL upstream walking recipe, unmodified, on OUR hardware.
> Exists only to answer **'is the veering our 8 recipe edits, or the HD-1910 hardware?'**"*

文件 `reference_official_velocity_env_cfg.py`（46 KB）是官方仓库那份配置的**逐字拷贝**。
**查过日志：从未训练过。**

**为什么这是最高价值的一步**：现在所有"对齐官方"的讨论都建立在一个未验证的前提上
——"官方的结果来自它的奖励配方"。但也可能来自：
- 它的**舵机**（`kp_fw=200` vs 我们 32，刚度差 6 倍）；
- 它的**硬件**（737 g vs 779 g）；
- 或者我们的 **DR 设置**。

跑它一次就能把这三者分开：

| 结果 | 结论 | 下一步 |
|---|---|---|
| 官方配方在**我们硬件**上走直、不外八、站得稳 | **是我们的 8 处配方改动造成的** | 二分那 8 处 |
| 官方配方在我们硬件上**也外八/也漂** | **是硬件或 DR**，改奖励没用 | 转向硬件/DR 方向，别再改奖励 |

无论哪个结果，都结束当前的猜测循环。**这是唯一一个"一次实验回答一个根本问题"的臂。**

### 1.2 `MICRODUCK_FEET_DISTANCE=1` —— 脚间距（任务层面，单关节绕不过去）

`microduck_velocity_env_cfg.py:1020` 已经接好了，默认关：

```python
if ENABLE_FEET_DISTANCE:
    cfg.rewards["feet_distance"] = RewardTermCfg(
        func=microduck_mdp.stance_feet_distance_penalty,   # 只在双支撑收费
        weight=FEET_DISTANCE_WEIGHT,                       # 默认 -2.0
        params={"min_dist": FEET_DISTANCE_MIN, ...},       # 默认 0.080 m
    )
```

它用的是 `stance_feet_distance_penalty` —— **只在双支撑期**对"两脚水平间距 < `min_dist`"收费。
cfg 里的注释写的正是新思路：

> *"这是**唯一一个改在任务层面、单关节绕不过去**的外八处方（关节空间的两种形状都已被实测证伪）"*

**为什么它和已证伪的两条不同**：

| 处方 | 约束的是 | 能否被绕开 |
|---|---|---|
| pose std → 0.05 | 关节**角度**的分布 | ✅ 被绕开（外八 0.454 → 0.583，更糟） |
| `hip_roll` L1 | **一个**关节的角度 | ✅ 被绕开（策略从膝/踝逃逸，站立崩掉） |
| **脚间距** | **脚在空间中的位置** | ❌ 这是任务目标本身；膝/踝怎么动都改变不了"两脚离得太近"这个事实 |

**查过日志：从未训练过。** 建议 `FEET_DISTANCE_MIN=0.080`（官方单环境实测踝间距 88 mm）
先跑一臂，权重用默认 −2.0。

> ⚠️ **一个必须注意的点**：`min_dist = 0.080` 这个数是**单环境**测出来的。
> 按 §9.7 的教训，**先用 64 环境量一次官方和我们基线的真实脚间距**再定这个阈值，
> 否则可能定出一个我们自己现在就已经满足（或永远满足不了）的数。

## 2. 需要新写代码的思路

### 2.1 ⭐ 把姿态约束从"逐关节**平均**"改成"整条腿**求和** L1"

**这是本轮分析里最有价值的一条，而且它解释了一个一直没说清的机制。**

走路任务的 `pose` 项是 `per_joint_posture`（`mdp.py:2049`），形式是
**逐关节高斯的算术平均**：

```
per_joint_posture = mean_j( exp(-err_j² / std_j²) )          ← 我们现在用的
```

它的 docstring 记录了自己替换掉 mjlab 版本的原因：

```
mjlab : exp(-mean_j(err_j²/std_j²))      ← 一个关节跑远，整项塌成 0，所有关节的梯度一起死
this  : mean_j(exp(-err_j²/std_j²))      ← 不会塌
```

**但这次实测暴露了它的反面代价**（docstring 里没有写）：

- `mean_j` 对**单个垮掉的关节**只扣 **1/N**（N=10 条腿关节）；
- R4 臂的左膝在零命令下偏 HOME **0.427 rad**，`std_standing` 的膝 std 是 0.15
  ⇒ 该关节因子 `exp(-(0.427/0.15)²) = 3.0e-4` —— 但它只让**整项**损失
  `(1 − 3.0e-4)/10 ≈ 0.10`，即约 **10% 的这一项**；
- **所以策略可以"用一个关节换掉整条腿的姿态"，只花 10% 的这一项。**

**这正是 R3/R4 从膝/踝逃逸的数学原因。**

⇒ **新思路**：保留 `per_joint_posture` 做**塑形**（它不该塌），
**另外加一条"整条腿求和"的 L1 做强制**（L1 的梯度在大偏差下恒定 —— 这是仓库自己反复用过的理由）：

```python
# zero-command / stance gated，作用于整条腿链
Σ_j relu(|q_j − HOME_j| − deadband_j)      # 求和，不是平均
```

**为什么求和能堵住逃逸**：现在 `joint_deviation_l1` **本身就是求和**（`mdp.py:2045`
`torch.sum(...)`），但被拆成了 `stance_hip_yaw`、以及我试过的 `stance_hip_roll`
—— **一次只管一组关节**，所以"绕道膝/踝"就成立。**把它改成一条覆盖整条腿链的项，
绕道就无处可去：从 hip_roll 挪到膝，只是把成本挪到同一项里。**

**deadband 要用实测的不可逃逸值**（仓库规矩），建议先零命令下量一次
`ck7000` 各关节的真实偏差，取其 ~1.5 倍作 deadband（`ck7000` 的膝 −0.072、踝 −0.093，
所以 0.10–0.15 量级），**不要拍脑袋**。

### 2.2 ⭐ 站立要有"目标姿态"，而不只是"别动"

现在管零命令的是 `stillness_at_zero_command`（`mdp.py:4026`）：
`exp(-body_vel²/vel_std²)` —— 它奖励**不动**。

**一个静止的深蹲完全满足它。** R4 就是活例子：它零命令下 tilt 46°、膝 ±0.43，
但它是"静止地塌着"。

而官方站立时**每一个关节都在 HOME ±0.03**。

⇒ **新思路**：零命令下把"**姿态对齐 HOME**"作为一等目标 —— 就用 §2.1 那条求和 L1，
按 `stillness_at_zero_command` 同样的**零命令闸门**接上去。
**"站着别动"和"站在标准姿态上"是两个不同的要求，现在只训练了前者。**

### 2.3 脖子：**别让它折**，而不是折了再罚

三次惩罚（`head_ground`、`neck_limit_proximity`、`head_pose_l1`）全部失败，
而且证据指向一个结构性原因：

```
Episode_Reward/dof_pos_limits（与奖励设计无关的旁观量，权重 -1.0 从第 0 步就在）
  iter 1   : -0.0025/s
  iter 100 : -0.1704/s      ← 折脖子在这里就已经发生
  iter 500 : -0.2421/s
```

而修复项的权重要到 **第 300 迭代**才爬上来，`head_pose` 指令范围要到第 **500 / 2000**
迭代才放宽 ⇒ **折脖子在修复项存在之前就形成了，之后所有惩罚只是在盆地底部加常数。**

⇒ **新思路：改结构，不改权重。**

| 选项 | 做法 | 代价 |
|---|---|---|
| **A. 脖子动作早期夹紧** | 训练前 N 迭代把 `neck_pitch` 的**命令偏移**限制在 HOME 附近，之后逐步放开 | 需要一个新的 action-level 课程；不改变收敛目标（官方就是 HOME） |
| **B. 改 spawn** | 出生时脖子就在 HOME（现在部分 spawn 是坐姿、脖子已折） | 改事件配置，风险低 |
| **C. 前 N 迭代冻脖子** | 直接把 `neck_pitch` 的动作清零，让它先学会"不折也能坐/走" | 最粗暴但最确定；之后放开 |

**A/B/C 的共同逻辑**：官方**坐着的时候脖子也在 HOME**（`neck_pitch +0.026`），
`SITTING_TARGET_OVERRIDES` 里也**明确没写脖子**（注释：*"neck/head intentionally
omitted → steered by the head_pose command"*）⇒ **折脖子从来不是任务需要的**，
它是策略在早期自己长出来的。**不让它长出来，比长出来再拔掉容易得多。**

### 2.4 观测里补一个"当前姿态离 HOME 多远"的特征（可选）

现在策略要维持姿态，只能从 `joint_pos(14)` 自己推断。加一个显式的
`Σ|q−HOME|` 或逐关节归一化偏差，让"姿态是否跑偏"在观测里**线性可读**。
**这是假设，不是结论** —— 先做 §2.1，如果 L1 仍然推不动再考虑。
