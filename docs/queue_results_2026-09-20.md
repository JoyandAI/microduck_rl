### 3.3 一个度量陷阱（顺带记下）

训练日志里 `Episode_Reward/flight` 在 flight 臂之间是 −0.3021 / −0.2468 / −0.2302，
看起来"s42 的飞行最多"，但探针测出来 s42 的 flight **最少**（0.0170）。

→ **不要用训练期累计惩罚量比较"飞行多少"，要用探针的归一化占比。**

## 5. 队列 provenance bug（重要，已修）

**症状**：`logs/queue_overnight/ours_flight_s42/43/44.onnx` 与 `logs/queue_routeA/` 的**逐字节相同**。

**原因**（`scripts/run_arm_once.sh:84`）：

```bash
run_dir="logs/rsl_rl/velocity/$RUNNAME"
[ -d "$run_dir" ] || run_dir=$(grep -o 'Logging experiment in directory: .*' "$TLOG" | tail -1 | ...)
```

`MICRODUCK_TASK_NAMED_RUNS=1` 遇到重名会把新 run 静默改名成 `<name>_r2`
（所以 overnight 重跑的 flight 变成了 `ours_flight_s4*_r2`），
但脚本先看"约定路径是否存在"——旧 run 的目录在，于是**沿用了旧目录**，
`ck=$(ls -t "$run_dir"/model_*.pt | head -1)` 导出的是**上一次训练的最后一个 checkpoint**。

**证据链**（三条独立）：
1. md5 相同（见上）；
2. ONNX `mlp.2.weight` == routeA `model_8999.pt`，max|Δ| = 0.000e+00；与 r2 的差 5.7e-01；
3. `results.tsv` 里记的 `run_dir` 也是旧路径（`logs/rsl_rl/velocity/ours_flight_s42`）。

**影响**：这 3 个臂的 ONNX / `_vx0.2.json` / `_vx0.0.json` / `_gait.json` / flight 探针
全部是 **routeA（r1）** 的策略；而它们的训练期指标（来自各自的 `_train.log`）是 **r2** 的 —— 
**同一行的两个数据源描述的是两个不同策略**。r2 那三次训练（~9 GPU·h）从未被评估过。

**修复**（已自测）：解析顺序反过来 —— **训练日志是权威**，约定路径只作兜底；
再加一道守卫：要导出的 checkpoint 的 mtime 必须晚于本臂开始时间 `T0`
（不能和 `TLOG` 比 mtime，因为日志最后一次 flush 比最后一个 checkpoint 晚 ~30 ms）。

```
ours_flight_s42 → logs/rsl_rl/velocity/ours_flight_s42_r2   ✅（修复前解析到非 r2 的旧目录）
ours_head_s43   → logs/rsl_rl/velocity/ours_head_s43        ✅
```

**影响范围**：只有"重名"的臂。`turn_*`、`ours_head_s43` 的 ONNX 是真的（md5 唯一）。
注意 `ours_yawdc s42` 队列里也已有同名 run（routeA 跑过），**修复赶在它之前生效了**，否则会重复同样的错。

## 8. 用户新问题："官方是不是也不完全走直线，用合理的转弯当转向？"（14:20 追加）

### 8.1 口径更正：官方在**它自己的模型**上几乎是完全直的（4.5°/20 s）

`logs/axis/j_official_0.2.json` 用的是**另一个模型文件**（模型不一样、官方并非训练在它上面），
所以我先前引用的 "2.8° / 走动环境 31.1°" 是**双重混淆**（错的模型 + 叠加了"是否在走"的条件）。
官方正确的参照是 **`preswap` 模型 + `xl330` 舵机**（它训练时的那套，也就是
`measure_flight_all.sh` 用来校准 D 的已发表数字所用的组合）：

| 官方 released，vx=0.2，wz=0 | 值 |
|---|---|
| 净转角中位（全部 64 env） | **4.5°** |
| 偏航速率（= 漂移斜率） | **−0.13 deg/s** |
| 通道截距（wz 扫描线性拟合） | −0.16 deg/s（等效转弯半径 72.9 m） |
| 增益对称性 | −0.6 → 54.8 %；+0.6 → 54.2 %（比 1.01） |
| 原地转向（vx=0, wz=±0.6） | 1.1 % / 5.2 % → **站着不能转** |
| 摔倒 | 0/64 |
| 20 s 里程 | 0.41 m（速度 0.0204） |
| **每米航向误差** | **11.1°/m** |

**结论：官方不靠"自然转弯"转向** —— 它的通道是过原点、左右对称的速率通道
（截距 ≈ 0），零命令时几乎不动不转，转向只在行走时发生。用户上一个问题的答案到此闭合。

按里程归一后（把"慢"和"直"分开）：

| 策略 | med\|Δψ\| | 速度 | 20 s 里程 | **每米误差** |
|---|---|---|---|---|
| 官方 released（preswap+xl330） | 4.5° | 0.0204 | 0.41 m | **11.1°/m** |
| align_fwd（官方配方+头块，m5） | 78.2° | 0.1177 | 2.35 m | **33.2°/m** |
| ck7000（m5） | 118.5° | 0.0891 | 1.78 m | 66.5°/m |
| ours_flight s42（m5） | 160.8° | 0.0261 | 0.52 m | 307.9°/m |
| ours_stance s42（m5） | 213.1° | 0.0339 | 0.68 m | 314.6°/m |
| ours_head s43（m5） | 571.1° | −0.0043 | 原地打转 | ∞ |

所以"落后"的正确量级是 **3–8×（最好臂 vs 官方，按里程）**，不是 40×；
但**最近排队的那一族是 30×**。

### 8.2 "每步转一点、不抵消"不是官方的样子 —— 而且它与直行度无关

在**全部 67 个策略/checkpoint**（统一 vx=0.2、20 s、≥8 个走路环境）上做相关：

| 自变量 | 与 log10(\|20 s 净转角\|) 的皮尔逊 r |
|---|---|
| `yaw_dc_body_deg_s`（净漂移速率） | **0.941** |
| `yaw_ac_lock_deg_s`（与步相锁定的偏航分量 = 左右半步冲量不等的"跑步机"分量） | **0.130** |

- DC 的高相关基本是同量积分，作为评估器一致性检查（DC × 20 s ≈ 净转角，逐条吻合）。
- **AC 与直行度几乎无关**：存在"每步几乎不摆、但偏置巨大"的策略
  （`align_official_ck08999`：|AC| 1.5 deg/s、|DC| 21.8 deg/s、净转角 421°）。
  ⇒ **"把每步扰动压小就能走直"是错的简化**；决定直不直的是**偏置 DC**。
- 官方两个量都小（AC 3.0 / DC 1.5），但它不是"转出去再抵消"，而是**步态本身几乎不产生旋转**
  （双支撑 0.554、小步 0.94 Hz、零飞行）。这正是 route A 想复制的物理。

### 8.3 它的转向机制确实是"旋转"，不是"重新落脚"（F 的测量）

官方转向 = 双支撑期（占 55 % 周期）的**共模竖直轴旋转**（`dss_sum` +15.65°/周期），
横向落脚只变 **±2 mm**。也就是说它把转向实现成"支撑相里把身体扭一下"，
而不是"把脚放到别的地方"。**用户"用转弯当转向"的直觉在机制层面是对的。**

但因果要分清：零命令时它**不保留净曲率**（48/52 无偏），命令来了才产生
57.6 % 增益的直流响应。所以那是"零输入零输出 + 输入有增益"的干净通道，
不是"拿自然转弯当转向"。

### 8.4 对我们的含义

1. **放宽直行约束不会换来转向能力**：我们的策略已经在一个方向上持续转 19–29 deg/s
   （官方的 13–19 倍），只是不受命令控制、方向抽签。允许"合理转弯"= 让这个抽签转弯长大。
2. 缺的是**命令驱动的直流通道**：官方 wz=0 → DC 1.5 deg/s 且无偏；给 ±0.6 rad/s →
   57.6 % 增益。我们要的是同样的"过原点 + 有增益"。
3. 正在跑的 `scripts/probe_official_steering.sh`（官方 wz=±1.0/±0.6/±0.3/±0.1、
   以及 vx=0 原地转、外加 ck7000 与 ours_flight_s42 对照）会给出通道形状
   （线性？过原点？左右对称？），并把官方**在我们的 m5 物理**上的 wz=0 基线补齐。
4. 上一条 §3 的结论要按同样口径重述：flight penalty 把**走路环境的**净转角
   从 452° 降到 107°、DC 22.9 → 5.6，但 **AC 没变**（32.6 → 24.1，同一档）
   —— 它动的是偏置，不是步态扰动的性质。这与 8.2 一致。
