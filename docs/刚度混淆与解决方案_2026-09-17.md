# 刚度混淆（kp_fw 200 vs 32）：如何把它变成可判定的实验，以及最终解决方案

> 起点：用户指出的混淆 —
> **官方跑 `kp_fw=200`，我们跑 `kp_fw=32`，位置环刚度差 6.25 倍。**
> ⇒ "官方几乎不动 / 我们抖" 这类**关于执行器输出的比较**被污染；
> 但 "官方所有关节都在 HOME" 是**策略属性**，与刚度无关。
> 同时：官方在我们硬件上 **0/5 存活、窗口 0.89 s**，所以**没法**把
> "官方策略更好" 与 "官方舵机更硬" 分开。
>
> 本文做两件事：① 把这条混淆**变成可判定的实验**；② 给出**叠加了两份清单之后**的解决方案。

---

## 1. 先把混淆量化：它不是"标度差异"，是"非线性区间差异"

`BAM` 的位置环是**纯 P**（`vendor/bam/bam/actuator.py:296`）：

```python
duty_cycle = (q_target - q) * self.kp * self.error_gain      # 再被 ±max_pwm 钳位
```

`error_gain = 0.163`（台架实测）。于是占空比在多大误差上打满：

| `kp_fw` | 占空比饱和于 | 含义 |
|---:|---:|---|
| **200（官方）** | `1/(0.163·200)` = 0.031 rad = **1.8°** | 误差 >1.8° 就满占空比；**在 1.8° 以内是真正的比例控制** |
| **32（我们）** | `1/(0.163·32)` = 0.192 rad = **11.0°** | 误差要到 **11°** 才满占空比；**11° 以内只有约 1/6 的修正力度** |

**这条比"刚度差 6 倍"更要紧**：

- 在 `kp=32` 下，一个 1° 的误差只产生 `0.163·32·0.0175 = 0.09` 的占空比，
  即**约 9% 的扭矩权限**。策略必须用**大得多的指令误差**才能拿到同样的修正力。
- 在 `kp=200` 下，1° 误差就有 `0.163·200·0.0175 = 0.57`，即 **57% 权限**。

⇒ **两台机器上"同一个动作数值"的物理含义完全不同。**
这不是 6 倍的线性缩放，而是**控制权限曲线的形状不同**。

### 1.1 直接后果：三个缺陷全部被污染

| 结论 | 被污染的部分 | 未被污染的部分 |
|---|---|---|
| "官方走路 z 波动 0.05 mm vs 我们 0.25 mm" | ❌ **整条比较作废**（负载下的静态下垂与抖动幅度直接由 kp 决定） | — |
| "我们的脖子停在 −1.934 rad" | ⚠️ **"为什么停在那里"被污染**（低 kp 下维持姿态需要巨大指令误差） | ✅ **位置本身**（`neck_pitch` 绝对角 −1.585 = 硬限位 −π/2，距限位 0.8°）与刚度无关 |
| "官方所有关节都在 HOME" | ⚠️ 官方在 kp=200 下**只需要接近零的指令**就能保持姿态，所以"输出≈0"是**低负载指令下的自然结果** | ✅ **但"它选择了 HOME"这个目标仍是策略属性**——刚度不决定**它想去哪**，只决定**它要花多大力气** |
| "外八 L−R = 0.454 rad" | ⚠️ 部分（低 kp 下重力会把腿压开） | ✅ 官方在 **同样低刚度时代？不——官方在自己的 200 上**，所以这条**也是混淆的** |

**⇒ 我先前那份评估里，凡是用"官方 vs 我们"做的执行器层比较，都需要打折；
凡是"我们自己仿真里、同一模型内的因果链"（冻结 `hip_yaw` 消融、
`hip_roll` L1 消融、8 条已证伪处方）**不受影响**——因为那些是**同一台机器内的受控消融**。

**这是本次最重要的方法论收获：**
> **跨硬件时代的 A/B 只能用来问"这个策略在它自己的机器上行不行"，
> 不能用来问"哪个策略更好"。**

## 2. 把混淆变成可判定实验：三组受控矩阵

关键工具已经存在：`MICRODUCK_KP_FW` 是**环境变量**（`microduck_constants.py:141`），
可以在**不重训**的前提下改执行器刚度。

### 实验 A（零训练成本，先做）—— **同一策略 × 刚度扫描**

对**同一份 ONNX**扫 `kp_fw ∈ {32, 64, 100, 200}`，测：

| 指标 | 测什么 | 判读 |
|---|---|---|
| `neck_pitch` 相对 HOME | 头是否展开 | 若**高 kp 下自己展开** ⇒ 低 kp 的"折头"是**控制权限不足**，不是策略选择 |
| L−R `hip_roll` | 外八是否收拢 | 同上 |
| 冻结 wz=0 的净偏航 | 走直是否改善 | 同上 |
| 动作幅度 `\|a\|` | 策略在**指令**多大的误差 | 若高 kp 下 `\|a\|` 大幅下降 ⇒ 低 kp 迫使策略输出大指令 |

**这条最关键**：它**不用重训**就能回答"三个缺陷有多少是刚度造成的"。
先前的 `action_scale` 实验（0.9 让速度掉 36%）已经证明**执行器口径的改动足以大幅改变策略行为**。

#### ⚠️ 4.1 这个实验**已经被跑过一次，而且跑了，但没用** —— 必须记录

我查到 `scripts/night_queue.sh` 里**已经有 arm B = `MICRODUCK_KP_FW=64`**
（"stiffer servo (sim)"），3 个种子 × 3000 迭代。**注意与实验 A 的关键区别：它换的是
"训练时的刚度"（stochastic，跨种子），而不是"同一策略的评测刚度"（deterministic）。**

我核对了它的参数确实生效（`params/env.yaml`: arm A `kp_fw: 32.0` / arm B `kp_fw: 64.0`），
结果是**不能用**：

| 臂 | 3 个种子的 `yaw_bias_deg_s` | 均值 | **臂内 SD** |
|---|---|---:|---:|
| A（kp=32） | −22.81 / +3.67 / +13.90 | −1.75 | **18.94** |
| B（kp=64） | −3.40 / +8.77 / +15.05 | +6.81 | **9.38** |

> **臂内 SD（18.94）是臂间均值差（8.55）的 2.2 倍**，n=3。
> AGENTS.md 已实测：**要分开类似的两臂，需要约 52 个种子/臂**
> （"4 arms × 3 seeds × 3000 iters 无法分开任何一臂；within-arm seed SD 超过 between-arm spread"）。

⇒ **这个 kp=64 臂回答不了刚度问题**，不是因为它设计错，而是因为**它用了随机变量（种子）
去测一个可以用确定性消融测的东西**。**这正是 AGENTS.md 里那条教训的又一个实例**：

> *"Prefer deterministic single-checkpoint ablations (one env, frozen command, no pushes)
> over comparing independently trained runs."*

**⇒ 所以实验 A 的正确形式是：**

```bash
# 同一份 ONNX、1 个 env、冻结指令、固定 seed，只改刚度 —— 确定性消融
for kp in 32 64 100 200; do
  MICRODUCK_KP_FW=$kp .venv/bin/python scripts/compare_walk_angles.py \
    --policy "kp${kp}:walk_hd1910_splayfix_6500.onnx" \
    --vx 0.2 --seconds 12 --seed 0
done
```

（`MICRODUCK_KP_FW` 经 `microduck_constants.py:143` → `kp_fw` →
`vendor/bam/bam/mjlab.py:221-222` 覆盖 BAM 的 `actuator.kp`，**无需重训**。
评测脚本不必显式引用它——导入 `microduck_constants` 时就已经生效。）

### 实验 B（零训练成本）—— **官方策略 × 我们的刚度**，但换问法

官方在我们硬件上 0/5、窗口 0.89 s，所以**"官方更好"无法直接测**。改为问一个能测的问题：

> **官方策略在 `kp_fw=32` 下，是"立刻摔"还是"能站但不走"？**

- 若**立刻摔** ⇒ 说明官方策略**依赖 200 的刚度**才能存活
  ⇒ "官方策略更好"**不可与"官方舵机更硬"分离**，该比较**永久作废**（写进结论，不再引用）。
- 若**能站住**（哪怕走不好）⇒ 说明差异主要在**步态策略**，刚度只影响走的质量。

### 实验 C（需要重训）—— **在 `kp_fw=200` 下重训一臂**

这是**唯一能真正打破混淆**的实验：**改变执行器、保持策略配方不变**。

- 若在 200 下训出来的策略：**头在 HOME、不走歪、不外八**
  ⇒ 结论是**我们给策略的执行器太软**，修法是**换舵机/提高刚度**，而不是继续调奖励。
- 若在 200 下训出来的策略**仍然折头、仍然走歪**
  ⇒ 结论是**奖励栈确实缺定价**，维持我先前那份评估的方案。

**⚠️ 注意 `kp_fw=200` 对 HD-1910 不是可部署配置**（真机固件 reg50 = 32）。
实验 C 的目的**只是判别**：它回答"缺陷是执行器造成的还是奖励造成的"，
**不产出交付件**。这点必须写清楚，否则会有人把它当成方案。

### ✅ 实验 A 已跑完（2026-09-17 15:07）—— 结果**否定了"刚度是主因"**

协议：**同一份 ONNX、同一 seed、冻结 vx=0.2、20 s、64 环境**（不是单环境——
AGENTS.md 已证明单环境绝对值可差 20–44× 且会翻转符号）。
标定：`ck7000` 在同协议下复现仓库记录的 **−0.47 deg/s**，**协议可信**。

| 策略 | `kp_fw` | **偏航率中位** | 前进速度中位 | tilt 中位 | 存活 |
|---|---:|---:|---:|---:|---:|
| `ck7000`（会走） | **32（训练值）** | **−2.15** | **0.088** | 2.8° | 64/64 |
| | 64 | −2.86 | 0.038 | 3.1° | 64/64 |
| | 100 | **+2.29** | 0.039 | 3.6° | 64/64 |
| | 200 | **+5.05** | **0.015** | 4.3° | 61/64 |
| `splayfix6500`（几乎不走） | **32** | **+10.20** | 0.016 | 3.0° | 64/64 |
| | 64 | +8.93 | 0.031 | 3.3° | 64/64 |
| | 100 | +1.99 | 0.030 | 3.9° | 64/64 |
| | 200 | **−2.65** | 0.010 | 4.6° | 63/64 |

**四条结论：**

1. **刚度不控制偏航，而且不单调。** `ck7000` 的偏航率 −2.15 → −2.86 → **+2.29** → +5.05：
   在 kp=100 处**符号翻转**。另一个策略 32→200 是 +10.20 → −2.65（**也翻转，方向相反**）。
   ⇒ 与 AGENTS.md 的判据一致：**"不对称的符号会翻转 ⇒ 不是系统性偏置，而是自发对称破缺"**。
   **若偏航源自舵机/机械不对称，提高刚度只会把它单调放大——实测是随机翻转。**

2. **提高刚度不会让我们的策略走得更好，反而更糟**：速度 **0.088 → 0.015 m/s（−83%）**，
   tilt 2.8° → 4.3°，kp=200 时有 **3/64 摔倒**。
   ⇒ 因为它**是按 kp=32 训练的**，把机器变硬等于换了一台它没见过的机器。

3. **所以"把舵机换硬"不是本缺陷的解决方案。** 硬舵机需要**重新训练**，
   而这正是**实验 C** 要回答的问题（不是"改刚度就能修好现在的策略"）。

4. **对用户那条混淆的判定**：
   - **高度波动 0.05 vs 0.25 mm** 那一类**比较确实作废**（静态下垂/抖动直接由 kp 决定）✅ 用户说对了；
   - 但**偏航不是刚度造成的**——提高刚度（若真有效）应当单调改善或单调恶化，
     实测是**符号乱跳**。⇒ **"走歪"仍归因于策略/奖励结构，不是刚度。**

**⚠️ 附带发现（要记住）**：`walk_hd1910_splayfix_6500.onnx` 在 64 环境协议下
**几乎不走**（0.016 m/s）。而同族的 `ck7000` 走 0.088–0.111 m/s。
⇒ **本文件以及"刚度混淆"相关的历史结论，凡是以 `splayfix_6500` 为被试的，都要重跑**
（它不是一个合格的步态被试）。

## 3. 最终解决方案（两份清单合并后，按"先判别、零成本优先"排序）

> **⚠️ 2026-09-17 15:00 重大更正**：`docs/experiment_report_2026-09-17.md` §9.3/§10.3
> 已把 **`hip_roll` L1 (`MICRODUCK_STANCE_HIP_ROLL`)** 判定为**错误方向、不要再开臂**：
> 它确实把外八从 0.43–0.48 降到 0.16–0.17（−62%），但
> **零命令存活率从 100% 掉到 0%、站立 tilt 2° → 47°（摔倒）**——
> 因为 L1 只约束髋 roll 一个关节，**策略从膝（±0.43 rad）和踝（±0.58 rad）绕了过去，塌成深蹲**。
> **任何单关节惩罚都不安全**（AGENTS.md 新条目）。
> ⇒ 我先前版本里"外八用 hip_roll L1 修"的建议**作废**；正确方向见第 2 阶段。

## 4. 这条混淆改变了我先前评估的哪些结论

**必须打折的（执行器层、跨硬件比较）**：

1. ❌ "官方走路 z 波动 0.05 mm vs 我们 0.25 mm" —— **作废**。
2. ⚠️ "官方关节都在 HOME、我们折头" —— **"折头的原因"要重判**；
   但"**观测到脖子贴死限位**"（−1.585 rad，距 −π/2 仅 0.8°）是位置测量，**不受影响**。
3. ⚠️ "官方 3° vs 我们 26° 外八" —— 部分混淆。

**不受影响的（同一模型内的受控消融）**：

1. ✅ **冻结 `hip_yaw` 消融**：净偏航 −11.79 → +4.02，**步速不变**。这是同一台机器内的消融。
2. ✅ **`hip_roll` L1 消融**：0.454 → 0.221。同上。
3. ✅ **8 条已证伪处方**（收紧 pose std 反向、镜像损失不可靠、`head_pose_l1` 致"不坐"…）。
4. ✅ **舵机模型辨识精度**：独立验证 0.0048 rad、跨几何外推、`kt` 实测 R²=0.998。
5. ✅ **`neck_pitch` 绝对角 = 硬限位 −90°**（距限位 0.8°，三阶段逐位相同 32/32）。
6. ✅ **颈部重力矩只需 12.8% 堵转**（0.187 N·m / 1.458 N·m，余量 7.8×）——
   **这一条恰好说明刚度不是唯一因素**：即使 kp=32，余量也有 7.8 倍。

**⇒ 净结论**：混淆**削弱**了"官方是更好的策略"这一论据，
**但没有**推翻"三个缺陷在仿真里就存在"这一事实——
因为后者由**同模型内的消融**支持，而不是由跨硬件比较支持。

## 5. 一句话

> 刚度混淆是真的，而且比"6.25 倍"更严重——它是**控制权限曲线形状**的差异
> （kp=32 时占空比要到 **11°** 误差才打满，kp=200 只需 **1.8°**）。
> **解决办法不是继续争论，而是用 `MICRODUCK_KP_FW` 做同一策略的刚度扫描（实验 A，零训练成本）**，
> 它直接给出"三个缺陷里有多少是刚度"；
> 再用**实验 C（kp=200 重训一臂）**判别"是执行器太软还是奖励缺定价"。
> **在实验 A/C 出结果之前，不要大规模重训，也不要再加奖励权重**——
> 两份清单在"不要靠 yaw 惩罚压偏航"这一点上完全一致，而它已经被 8 条失败处方证明过。
