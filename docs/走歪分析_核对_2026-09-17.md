# 对《走歪分析.md》的逐条核对：哪些成立、哪些被数据排除

> 对象：`docs/走歪分析.md`（2026-09-17 加入）
> 方法：把该文的每条假设与**本仓库已有的实测数据**逐条对照；能算的当场算，
> 不能算的明确标出"需要哪个实验"。
> 结论先行：**该文的第 19 节其实已经把判据写对了，但第 2/17 节的优先级表选错了分支。**

## 0. 一句话

《走歪分析》的诊断树是对的，**但本仓库的数据已经能走完这棵树**：

```
该文第 19 节的三个分支：
  (a) 换 actuator + 同一 policy → 转        ⇒ 查 actuator / calibration
  (b) 仿真直走 + 真机转                      ⇒ 查 sim2real gap
  (c) 仿真里就已经转                         ⇒ 查 BAM / 对称性 / zero   ← 该文说走这条
```

**实测落在 (c)，但 (c) 的结论与该文写的不一样。**

> **本仓库的仿真在左右方向上是"完美镜像对称"的**（下面 §2 有逐项实测），
> **而策略在它里面学会了左右不对称的步态并因此绕圈。**
> ⇒ 不对称不是仿真注入的，是**策略自己产生的**。
> (c) 分支要查的不是 BAM 对称性（它本来就是对称的），而是
> **"为什么在一个对称环境里，奖励允许策略收敛到不对称解"**。

一句话：**该文把"现象"(左右冲量失配) 当成了"病因"(左右动力学不对称)。**

## 2. ⭐ 核心分歧：该文第 5 节"左右不对称"—— 仿真里**不存在**

该文把"左右 HD1910 动力学不对称"列为**第 1 优先级（★★★★★）**，
推理是"左右微小差异 → 每步一点 yaw → 累积 → 转圈"。

**这个推理本身没错，但前提在本仓库不成立。我把仿真的对称性逐项测了：**

| 检查项 | 实测 | 结论 |
|---|---|---|
| **官方对称性审计**（`scripts/check_lr_symmetry.py`，仓库权威工具，2026-09-17 14:30） | 正运动学镜像误差 **0.0000 mm**（200 次随机镜像姿态）、肢体质量差 **0.000000 g**、世界系惯量位置镜像误差 **0.00000 mm**、主惯量差 **0.000e+00**、HOME 质心横向偏移 **0.031 mm**、关节 damping/armature/frictionloss 五对**完全相同**、执行器 gear/gainprm 相同 | ✅ **模型没有任何左右不对称** |
| 左右肢体**质量**（我另外独立复核 `robot_walk.xml` / `robot_allcollisions.xml`） | `upper_leg_left/right`、`leg/leg_2`、`ankle_left/right` 三对**逐对完全相同**；**总不对称 = 0.000 mg** | ✅ **与权威工具一致** |
| BAM 参数表 | **14 个关节共用同一张 `m5.json`**（`target_names_expr=(r"^(?!passive_).*",)`） | ✅ 无左右之分 |
| 每侧独立的 DR | **不存在**（DR 是 per-env，不是 per-side） | ✅ 无左右之分 |
| HOME 姿态 | `left_hip_roll = −0.0873` / `right_hip_roll = +0.0873`（**精确镜像**） | ✅ |
| `hip_roll` 行程 | 左右都是 `[−0.3840, +0.3840]` | ✅ |
| `hip_yaw` 行程 | 左 `[−0.4363, +0.5236]` / 右 `[−0.5236, +0.4363]` | ⚠️ **镜像但不对称**（见 §3） |
| 观测里的 encoder bias | per-env 采样，**不是 per-side** | ✅ |

⇒ **训练环境的左右是完全对称的。** 那台策略是在一个对称的仿真里
**自己学出了左右不对称的步态**。

**这一步是决定性的**：
- 如果不对称是**仿真/舵机模型注入**的 ⇒ 该文的 (c) 分支成立，去查 BAM/calibration。
- 如果环境对称、策略仍然不对称 ⇒ 不对称**源于策略**，(c) 分支要查的是**奖励**。

**而"环境对称"这一条是可以直接验证的、我已经验证了。** 所以是后者。

### 2.1 该文其实自己写对了判据

该文 §19 的三分支判据是**正确的方法论**。问题只在于：**它没有去读 (c) 分支下
"环境是否对称"这个前置条件**，直接假设了"不对称必来自硬件"。

### 2.2 一个该文没考虑到的替代解释（本仓库的实测支持它）

仓库里的因果链（`docs/q1_q2_root_cause_2026-09-16.md`）：

| | 左单支撑 | 右单支撑 | 加权净偏航 |
|---|---:|---:|---:|
| 我们 | **−42.79 deg/s** | **+23.01** | **−10.78 deg/s** |
| 官方 | −1.80 | **+1.79** | **−0.65**（抵消到 0.01） |
| 我们 + **冻结 `hip_yaw`** | **−0.15**（降 285×） | +7.56 | **+3.81**（翻正） |

**官方也有偏航冲量，而且两侧几乎完全相等（−1.80 / +1.79）** ⇒ 官方零成本地做到了
"左右对称"。我们两侧**幅值差 1.9 倍**才转圈。

⇒ **缺的不是对称的硬件，是"要求对称"的压力。** 奖励栈里
**没有任何一项给"走路时的净偏航率"定价**，所以"左右幅值相等"这件事
**既不奖励也不惩罚** —— 策略落进哪个盆地纯属偶然。

**这与"actuator 不对称"的区别是可判定的**：
actuator 不对称会给出**固定方向**的偏航偏置；
而"没有定价"会给出**随机的、由盆地决定的**符号（换个种子/检查点就可能反向）。

## 3. ⚠️ 该文的方向是对的，但漏掉了"镜像 vs 对称"这个区别

该文 §6 强调"尤其要检查右侧镜像安装的关节"——**这个提醒在本仓库确实有落点，
但性质与它设想的不同**。我实测到一个真实的**范围不对称**：

```
left_hip_yaw   range = [-0.4363, +0.5236]   ( −25.0° … +30.0° )
right_hip_yaw  range = [-0.5236, +0.4363]   ( −30.0° … +25.0° )
```

**这是"镜像"而不是"对称"**：把左边的范围取镜像，得到的是 `[−0.5236, +0.4363]`
（即右边的），**而不是它自己**。也就是说：
**左髋偏航的"向内/向外"行程比右边少 5°。**

**它会不会造成转圈？实测：不会。**
- 观测到的 `|hip_yaw|` 在走路时只有 **0.02–0.04 rad**；
- 两侧余量分别是 **0.4363 / 0.5236 rad**，是实际用量的 **10–20 倍**；
- 而且"贴限位比例"实测为 **0.0%**。

⇒ 这是一个**真实的、值得记录的建模不对称，但它不是转圈的原因**（余量差 20 倍）。
**该文的"镜像检查"方向正确，但要把"镜像 ≠ 对称"分开讲**，否则会去修一个不痛的地方。

**仍然值得做的镜像检查（该文 §6 的清单，我建议保留）**：

| 项 | 现状 | 建议 |
|---|---|---|
| 左右 `hip_yaw` 行程镜像性 | 已发现（上面） | 决定是否统一为 ±0.48（去掉 5° 差） |
| 真机左右舵机的 `q_offset` | **未测** | 台架逐舵机测（现有 72 条数据只有 **1 只**舵机） |
| 真机左右方向符号 | **未测** | 逐个关节发小角度、读回符号 |
| 真机左右 `duty`/电流 | **未测** | 站立保持时逐舵机读 `reg60`/`reg69` |

## 5. 该文 §20 的"三个实验"：两个已被现有数据回答，一个仍值得做

| 该文实验 | 现状 | 结论/建议 |
|---|---|---|
| **实验 1**：同一 policy × (官方 actuator vs HD1910 actuator)，看 yaw rate | ✅ **已做（交叉硬件矩阵）** | 官方策略放 HD-1910 硬件：**0/5 存活，窗口仅 0.89 s** ⇒ **比值指标不可引用**。真正的结论是：**两个策略各自只在自己训练的舵机上活得下来**——这**支持**该文"actuator 动力学极其重要"，但**不证明**"左右不对称"。⚠️ 且注意：这个对比混淆了**绝对差异**（kp_fw 200 vs 32、XL330 vs HD-1910）与**左右差异**，两者不是一回事。 |
| **实验 2**：左右 BAM 参数交换，看偏航方向是否反转 | ⚠️ **可做但预期无信息量** | 因为**左参数 == 右参数**（同一张 `m5.json`），交换后是**逐字节相同**的模型 ⇒ 输出必然完全一致。**这个实验必须先在"两侧参数不同"的前提下才有意义**，而本仓库的仿真里它们相同。 |
| **实验 3**：真机 vs BAM 阶跃响应（position/velocity/current/delay） | ⚠️ **最值得做，但需要台架** | 这是**唯一**能把"真机残差"量化的一步。现有辨识只用了**1 只舵机**，且 `pending_tests` 里作者自己列了 9 项未做（多舵机一致性、机器人侧关节零位与 URDF 对应、控制滞后/速度滤波项、过流保护真实行为…）。 |

### 5.1 我为此设计的替代实验（更能判别"谁产生不对称"）

由于实验 2 在对称仿真里没有信息量，我改设计了一个**直接测量"不对称是谁产生的"**的实验：

> **测量策略自己输出的 `hip_yaw` 动作的左右幅值比。**
>
> - 若**动作幅值比 ≈ 1.0** ⇒ 策略对称地命令两条腿 ⇒ 不对称来自物理/建模 ⇒ 该文正确。
> - 若**动作幅值比 ≫ 1** ⇒ **策略本身就在命令不对称的偏航冲量** ⇒ 不对称源于策略 ⇒ 修奖励结构。
>
> 因为仿真的舵机模型是镜像的，**任何动作上的不对称都只能是策略学出来的**。

已实现在 `scripts/compare_walk_angles.py` 的新表 `=== ACTION asymmetry ===`，
同时给出**冻结 wz=0 下的净偏航**（wrap-safe 逐步累加，避免本仓库踩过的
"包裹欧拉角相减读出 +107° 而真实是 −14.3°"那个坑）。

**⚠️ 状态：尚未跑出结果。** 第一次跑与续训的 W4 抢显存被杀；待 W4 跑完即跑。

## 6. 该文没提到、但对"真机比仿真更差"更关键的三件事

按对实际现象的解释力排序：

1. **⚠️ 整机质量差 12%（779.2 g vs 文档 874 g）** —— 唯一能造成"系统性下垂/变软"的
   **确定性**建模误差。背隙/失速起始只给残差，不会给系统性偏差。**先称重。**
2. **⚠️ 部署侧与训练不一致**：`action_scale` 原为 0.9（训练 1.0）——
   **我已实测**：0.9 让步速掉 **36%**；另有低通 0.5/0.7（训练里没有）——
   实测**近似无害**（−4.7%）。**这一条该文完全没有提到，而它是零成本可修的。**
3. **⚠️ 舵机 100 Hz 控制环其实不是问题**（我先前写错过，已更正）：
   `characterization.json` 的 `control_period_reg81=10` 自带注记
   *"语义未证实：T2 实测 reg60 变化间隔中位 1.17ms → 非 10ms 阶梯"*。
   真正缺的是**控制滞后/速度滤波项**与**D 强度**（`d_scale` 标着 `assumption`，
   台架数据**在原理上分辨不了**，需硬件 T5）。

## 7. 修正后的排查顺序（结合该文与实测）

**真机侧（该文的价值所在，全部未做，需要你动手）**

1. **称重**（779 g vs 874 g）—— 5 分钟，可能是最大的一条。
2. **读真机母线电压 + 固件寄存器**（kp/kd/ki、reg81、reg15），与 `characterization.json` 回读值对照。
3. **逐舵机测 `q_offset` / 方向符号 / 站立保持 duty**（左右各 7 个）—— 该文 §6 的清单。
4. **真机 vs BAM 阶跃响应**（该文实验 3）—— 量化真机残差。

**仿真侧（修缺陷本身）**

5. **`action_scale` = 1.0**（✅ 已改）；**低通在部署侧关掉**（实测无害，不必重训）。
6. **外八**：`hip_roll` L1 **收窄/去掉 deadband** 并改**对称目标**。
7. **走直**：不是加 `yaw_penalty`（该文对，且已被证伪），而是
   **让偏航通道变得可达** —— `MICRODUCK_TURN_FIRST` 课程（先学转弯，再学前向极限环），
   或净偏航率定价（`MICRODUCK_YAW_DC`）。**两个臂都还没被证伪，只是被中止。**
8. **头下垂**：先导出 iter 100/500/1000 确认"折脖子"发生的时间点，再决定改奖励还是改 spawn。
