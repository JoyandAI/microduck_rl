## 1. 为什么必须跑多个 run，而不是一次 A/B

今天量到的事实（`docs/forensics/走歪归因报告.md`）：

| 方差来源 | 路径效率跨度 |
|---|---|
| **同配置、同种子（都是 42）**，只差迭代数（3500 vs 12000） | **0.569 vs 0.124 → 0.445** |
| **同一 run 内**不同检查点（本次 run 6 个检查点） | **0.489 vs 0.043 → 0.446** |
| 官方 vs 我们（我先前以为的"差距"） | ~0.2（且大部分是种子噪声） |

**三者同量级。** 所以单次 run 的 A/B 等于掷骰子 —— 这是本队列每臂跑 **3 个种子**的原因。

## 2. 四个臂（每臂 3 个种子，各 3000 迭代 @ 2048 环境）

| 臂 | 配置 | 奖励项 | kp_fw | 隔离的变量 |
|---|---|---|---|---|
| **A** | 我们的配方（现状） | 22 | 32 | 基线 |
| **B** | A + 仿真舵机刚度翻倍 | 22 | **64** | **舵机刚度** |
| **C** | 官方配方 + `heading_hold` | 19 | 32 | **我们加的 3 项"腿税" + 2 项改实现** |
| **D** | 官方配方原样（`origin/develop@3412ae5`） | **16** | 32 | **官方基线** |

**对比设计**：
- `D vs C` → 隔离 `heading_hold` 单独的作用
- `A vs C` → 隔离我们相对官方多出的 3 项腿约束（`stance_hip_yaw` / `action_over_limit` / `neck_motion`）+ 2 项改实现（`per_joint_posture` / `air_time` 门控）
- `A vs B` → 隔离舵机刚度（**唯一直接松开物理约束的杠杆**）

种子：42 / 43 / 44。3 并发，GPU 内存守卫，每个 job 独立 `experiment_name`（避免取错 run 目录）。

## 3. 每臂的开关是怎么实现的

一组**环境变量实验钩子**（默认值 = 提交时的行为，不设变量则完全不变）：

| 环境变量 | 作用 | 位置 |
|---|---|---|
| `MICRODUCK_KP_FW` | 覆盖仿真固件 P 增益（真机 reg50 必须一致） | `robot/microduck_constants.py` |
| `MICRODUCK_STANCE_HYGIENE` | 关掉 `stance_hip_yaw`/`action_over_limit`/`neck_motion` | `tasks/microduck_velocity_env_cfg.py` |
| `MICRODUCK_PER_JOINT_POSTURE` | `pose` 回到官方 `variable_posture` | 同上 |
| `MICRODUCK_AIR_TIME_GATE` | `air_time` 回到官方 `feet_air_time` | 同上 |

每次 run 都把**解析后的完整配置**存进 `params/env.yaml`，所以加了钩子也不损失可复现性。

## 5. 怎么读结果（预先登记判据，避免事后编故事）

| 观察 | 结论 |
|---|---|
| 臂 B 明显优于 A（且分布不重叠或差距 > 2×σ） | **刚度是主因** → 上台架验证 reg50 64/96，改真机 + 改仿真 `kp_fw` + 重训 |
| 臂 C 明显优于 A | **我们的 3 项腿税是主因** → 逐个消融定位到具体哪一项 |
| 臂 D 明显优于 C | `heading_hold` **有害** → 回退 |
| 臂 C 与 A 无差异 | 腿税不是主因 → 回到硬件方向 |
| 所有臂分布大幅重叠（跨臂差异 ≪ 臂内差异） | **配方无法决定结果** → 结论是"这台平台上航向不可控"，应转向 **检查点精选 + 更长训练 + 硬件刚度** |
| 某臂某个 run 出现 eff ≥ 0.65 且 \|yaw\| ≤ 1.0 | 该检查点即为**可交付候选**，用 64 环境确认后再上真机 |

⚠️ **不要**只看各臂均值就下结论 —— 3 个 run 的均值的标准误仍在 0.15 量级。要看**整个分布**。

## 6. 已知的坑

1. **仿真 kp 的精确缩放语义未确认**（文档写明"mode 4 的 P/D 缩放 1/8、1/4 待官方表"）。所以臂 B 只能回答"**刚度方向是否有用**"，不能回答"reg50 具体该写多少"。
2. 臂 B 的 `kp_fw=64` **只改仿真**。若要上真机，必须真机 reg50 同步改，否则策略不迁移。
3. 零命令站定的行为**学得晚**：3000 迭代通常还在踏步（膝摆动 18°），12000 迭代才到 0.35°。若验收要求"零命令站定"，3000 迭代的结果不能作为否证。
