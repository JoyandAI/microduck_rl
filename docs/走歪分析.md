# MicroDuck RL：官方舵机替换为 HD1910 后出现行走转弯问题的分析与排查方案

## 1. 问题描述

当前基于 `JoyandAI/microduck_rl` 进行 MicroDuck RL 行走训练：

- 官方舵机版本训练出的 walking policy 可以基本保持直线行走。
- 将官方舵机替换为 **HD1910** 后，即使已经配置 BAM，并保持任务、PPO、reward 等主要训练设置一致，训练出的模型仍存在明显问题。
- 典型现象：机器人可以行走，但会持续向某一侧转弯，无法像官方模型一样保持直线。

核心问题：

> 为什么更换 HD1910 后，同样的 RL 任务和训练方式，会出现持续 yaw drift / 转弯？

---

## 2. 初步结论

目前最值得优先排查的不是 PPO 本身，而是：

```text
HD1910 真实动力学
        ↓
BAM actuator model
        ↓
joint position / velocity / torque response
        ↓
左右腿动力学对称性
        ↓
walking gait
        ↓
yaw drift
```

尤其怀疑以下问题：

1. HD1910 左右舵机动力学不一致
2. 零位 / 方向 / calibration 存在误差
3. HD1910 BAM 参数没有经过充分的实测辨识
4. 电压、电流和负载下的扭矩能力与仿真不一致
5. friction 参数不匹配
6. backlash 参数不匹配
7. simulation observation 与真实 encoder feedback 不一致
8. 机械安装误差导致左右腿不对称

不要首先通过修改 reward 强行压制 yaw，否则可能只是让 policy 学会补偿错误的 actuator model。

---

# 3. MicroDuck RL 的基本控制链路

可以将整个训练过程理解为：

```text
velocity command
       ↓
      PPO
       ↓
14 DOF action
       ↓
BAM actuator
       ↓
MuJoCo dynamics
       ↓
robot motion
       ↓
observation + reward
       ↓
PPO update
```

对于 walking task，策略并不是简单学习固定的腿部动作，而是在学习：

```text
给定：

vx = 目标前进速度
vy = 目标横向速度
yaw_rate = 目标角速度

如何控制 14 个关节，
使机器人：

1. 向目标方向运动
2. 保持身体稳定
3. 控制 yaw
4. 满足能量 / 动作等约束
```

因此，如果 HD1910 的 actuator dynamics 与训练环境不一致，最终可能出现：

```text
相同 command
      ↓
不同 actuator response
      ↓
左右腿实际运动不同
      ↓
产生额外 yaw torque
      ↓
机器人持续转弯
```

# 4. 为什么“有 BAM”仍然可能不够

一个常见误区是：

```text
官方舵机
↓
BAM

换成 HD1910
↓
BAM

所以应该一样
```

实际上 BAM 只是 actuator dynamics 的建模方式。

一个舵机实际包含很多影响机器人运动的因素：

```text
Position response
Velocity response
Torque response
Friction
Backlash
Latency
Output stiffness
Voltage dependence
Current limit
Temperature
Gear ratio
Encoder resolution
Zero offset
Direction
Mechanical installation
```

因此真正需要匹配的是：

```text
HD1910 Real Hardware
        ↓
System identification
        ↓
HD1910 actuator model
        ↓
BAM
        ↓
MuJoCo
```

而不是简单：

```text
官方 BAM
+
HD1910 名称
```

---

# 5. 第一优先级：左右动力学不对称

这是目前最值得怀疑的问题。

理想情况下：

```text
Left actuator ≈ Right actuator
```

但真实机器人可能出现：

```text
τ_left  = 1.00 × τ_model
τ_right = 0.90 × τ_model
```

或者：

```text
friction_left  ≠ friction_right
backlash_left  ≠ backlash_right
response_left  ≠ response_right
```

即使每一步只有非常小的差异：

```text
左腿推进：10.0 cm
右腿推进：9.8 cm
```

单步看起来几乎没有区别。

但经过很多步之后：

```text
每一步产生一点 yaw
        ↓
yaw 累积
        ↓
机器人持续转弯
```

这非常符合当前现象。

---

# 6. 第二优先级：Zero / Direction / Calibration

双足机器人对于左右关节的零位非常敏感。

例如仿真：

```text
left_hip_pitch  = 0°
right_hip_pitch = 0°
```

真实机器人：

```text
left_hip_pitch  = +1.2°
right_hip_pitch = -0.4°
```

那么左右之间已经存在：

```text
1.6° 的相对误差
```

可能进一步造成：

```text
足端位置不同
↓
步幅不同
↓
地面接触不同
↓
yaw torque
↓
转弯
```

除了 zero，还必须检查：

```text
Direction
Encoder sign
Gear ratio
Position scale
Joint limit
Motor ID
Mechanical zero
```

尤其要检查右侧镜像安装的关节。

例如：

```text
Simulation:

q_right = +10°

Real encoder:

encoder_right = +10°
```

但如果机械坐标系要求：

```text
q_right = -encoder_right
```

那么方向定义就错了。

---

# 7. 第三优先级：HD1910 BAM 参数是否真正经过辨识

建议不要只确认 BAM “可以运行”，而要验证参数是否与实际 HD1910 一致。

重点关注：

```text
Voltage
Current
Position response
Velocity response
Torque response
Friction
Backlash
Latency
```

建议实际采集：

```text
target position
actual position
target velocity
actual velocity
current
voltage
```

然后建立：

```text
target
  ↓
HD1910
  ↓
actual response
```

再和 BAM：

```text
target
  ↓
BAM
  ↓
simulated response
```

进行比较。

# 8. 特别注意 BAM 与 friction

MicroDuck RL 的 BAM actuator 对 friction 的处理方式值得特别关注。

不要简单认为：

```python
dof_frictionloss
```

修改以后，BAM actuator 的摩擦就已经被正确修改。

如果 BAM 自己计算 actuator friction，那么真正生效的可能是 BAM 内部的 friction / scale 等参数。

因此必须确认：

```text
你修改的 friction 参数
        ↓
是否真的进入 BAM actuator
        ↓
是否影响最终 torque
```

否则可能出现：

```text
以为已经做了 friction randomization
              ↓
实际上 BAM friction 没有改变
```

---

# 9. 电压问题

HD1910 的实际供电条件必须与仿真保持合理一致。

例如：

```text
Simulation:
Vin = 12 V

Real:
Vin = 11.2 V
```

在高负载状态下可能导致：

```text
available torque ↓
```

而双足机器人左右腿的瞬时负载并不完全一样，因此可能出现：

```text
Left leg torque response
        ≠
Right leg torque response
```

最终表现成：

```text
yaw drift
```

因此需要记录：

```text
Voltage
Current
Joint load
```

尤其是 stance leg 在支撑阶段的数据。

---

# 10. Backlash 问题

MicroDuck RL 已经考虑 backlash，因此换成 HD1910 后不能默认沿用官方舵机的 backlash 参数。

例如：

```text
Official servo:

backlash = ±0.5°

HD1910:

backlash = ±2°
```

如果仍然使用：

```text
±0.5°
```

那么仿真中的关节会比真实机器人“更紧”。

真实机器人：

```text
target changes
      ↓
gear moves inside backlash
      ↓
output does not immediately respond
```

而仿真：

```text
target changes
      ↓
output almost immediately follows
```

这会明显影响：

```text
foot placement
ankle control
hip yaw
hip roll
```

最终可能产生 walking yaw drift。

# 11. 最重要的实验：同一个 Policy 对比两种 actuator

不要一开始继续长时间训练。

先做：

```text
官方训练好的 policy
        ↓
      same obs
        ↓
      same action
        ↓
 ┌───────────────┐
 │ Official servo │
 │ HD1910 model   │
 └───────────────┘
```

然后比较：

```text
Base position
Base velocity
Base angular velocity
Yaw
14 joint positions
14 joint velocities
Joint tracking error
```

特别关注：

```text
base_ang_vel_z
```

也就是 yaw rate。

如果：

```text
Official:

yaw_rate ≈ 0

HD1910:

yaw_rate > 0
```

并且 HD1910 始终偏向同一个方向，那么基本可以确认：

> HD1910 actuator / mechanical model 产生了系统性的 yaw bias。

# 12. 左右参数交换实验

这是一个非常有价值的定位实验。

假设现在：

```text
HD1910 policy：

一直向左转
```

将：

```text
Left actuator parameters
↔
Right actuator parameters
```

进行交换。

如果结果变成：

```text
一直向右转
```

那么几乎可以直接锁定：

```text
左右 actuator / calibration / dynamics
存在系统性不对称
```

这个实验比直接修改 reward 更有诊断价值。

# 14. 不要只看 Position Error

建议至少记录四类数据。

## 14.1 Position tracking error

```text
e_q = q_target - q_actual
```

## 14.2 Velocity tracking error

```text
e_v = dq_target - dq_actual
```

## 14.3 Current / Torque

如果 HD1910 可以读取：

```text
current
```

记录：

```text
I_left
I_right
```

## 14.4 Base yaw

记录：

```text
yaw
yaw_rate
```

特别推荐分析：

```text
joint tracking error
        ↓
yaw_rate
```

之间是否存在明显相关性。

# 15. 为什么不建议首先修改 Reward

例如现在：

```text
机器人向左转
```

不要第一时间增加：

```python
yaw_penalty
```

原因是：

```text
错误 actuator model
        ↓
产生 yaw bias
        ↓
reward 强制惩罚 yaw
        ↓
policy 学会补偿
```

最终可能变成：

```text
Simulation:
看起来可以直走

Real:
仍然转弯
```

正确顺序应该是：

```text
先修 actuator model
        ↓
再验证 calibration
        ↓
再验证 dynamics
        ↓
再训练
        ↓
最后才调整 reward
```

# 19. 最终判断思路

如果出现：

```text
Official actuator
+ official policy
→ straight

HD1910 actuator
+ same policy
→ turning
```

并且：

```text
HD1910 yaw_rate
```

存在稳定偏置，那么重点就是：

```text
Actuator / calibration / dynamics
```

如果：

```text
HD1910 simulation
→ straight

Real HD1910
→ turning
```

那么重点转向：

```text
Sim2Real gap
```

尤其：

```text
calibration
mechanical installation
friction
backlash
voltage
torque
encoder feedback
```

如果：

```text
HD1910 simulation

```

那么应该优先修：

```text

左右对称性
zero
direction
friction
backlash
```

而不是继续调整 PPO。

# 21. 核心结论

当前现象：

> 官方舵机训练出来可以直走，而 HD1910 训练出来会持续转弯。

更合理的分析路径是：

```text
更换 actuator
      ↓
动力学改变
      ↓
左右 symmetry 被破坏
      ↓
walking gait 产生微小 yaw bias
      ↓
PPO 学到这个 gait
      ↓
最终表现为持续转弯
```

因此最优先检查：

```text
1. HD1910 calibration
2. 左右方向 / zero
3. 左右 actuator symmetry
4. BAM 参数
5. friction
6. backlash
7. voltage / torque
8. observation / encoder
```

**不要首先修改 reward 或 PPO。**

真正的目标应该是：

```text
Real HD1910
      ≈
HD1910 BAM
      ↓
correct symmetry
      ↓
correct simulation
      ↓
PPO
      ↓
stable straight walking
```
