## 结论(3 行内)

1. **默认配方里唯一给偏航定价的项是 `track_angular_velocity`**（weight 2.0、std=√0.5，`[cfg:1319-1320]`+`[mj:47-64]`）；
   它对**持续偏航率偏置 b** 的定价是**二次型 `−0.543·b²`/步**：实测每-env 偏置 `|b| = 0.1001 rad/s`
   ⇒ 只收 `−0.0054/步 = 总奖励(6.749/步)的 0.080%`；其余"偏航相关"项对 `∂/∂ω_z` 全部 ≤ `3e-4/步`
   （`body_ang_vel` 构造上恒为 0、`air_time` 只看指令 ⇒ 恒为 0、`pose` 对 hip_yaw 只有 `1.2e-4/rad` ⇒ 死）。
2. **两个方向坏法不同**：**走直线 = 定价不足**（比自己的"完美跟踪"上限少给 3.30–3.34% 的总奖励；
   按 std 归一后 DC 梯度只有同族 `track_linear_velocity` 的 **1/6.1**）；
   **转弯 = 定价被稀释 + 通道不可达**（完美转弯上限只有 +0.28~0.37/步 = 4.3–5.8%，
   而 ±0.6 rad/s(±34.4 deg/s) 指令只换来 **+3.45 / −7.19 deg/s** 的实际净偏航率，且 `|ω_z|` 在所有工况恒为 0.87–0.94 rad/s）。
3. **唯一改动：打开 `MICRODUCK_YAW_DC=1`**（`mdp.yaw_dc_rate_penalty`，weight **3.0** / `tau_s` 0.8 /
   门控 `|cmd_wz|≤0.15` 且 `‖cmd_xy‖>0.05`，300 迭代爬坡）——把偏航率定价从 **`−0.543·b²`（二次、b→0 处无梯度）**
   换成 **`−3.0·|b|`（线性、处处非零）**：实测工作点上偏差部分从 `−0.0054/步` 升到 **`−0.300/步`（55.6×）**，
   边际斜率 **27.6×**，消除偏置可赚回 **+0.290/步 ≈ 总奖励 4.3%**；它门控在直线指令 ⇒ 不与转弯打架，
   且作用在 `base_ang_vel`——**61 维观测里 actor/critic 真正看得见的那一个偏航量**。
   （风险如实记账：`−0.455/步` 的总收费里有 `0.156/步 = 2.3% 总奖励` 是对步态自身偏航摆动经 EMA 泄漏的税。）

## 是定价不足还是不可达

**两个通道必须分开回答：走直线的偏航率通道 = 定价不足（结构性）；转弯通道 = 定价被稀释 + 不可达。**

### (a) 走直线：定价不足，而且是"形状"错，不只是"权重"小

`track_angular_velocity` 对 ω_z 的偏导 `∝ (ω_z−cmd_z)·exp(−E/std²)` `[mj:61-64]`。
在工作点上：

```
|ω_z| 幅度均值        0.873 rad/s        ← 步态自身的偏航摆动
每-env 持续偏置 |b|   0.1001 rad/s       ← 真正想消灭的量（比值 8.7×）
带符号 ∂/∂ω_z         −0.0518
幅度   |∂/∂ω_z|        0.340            ⇒ 只有 15.2% 存活，84.8% 因符号翻转抵消
对照 track_linear     +0.709 / 1.052 = 67.4% 存活
按 std 归一：偏航 0.0518×0.707 = 0.0366 ；线速度 0.709×0.316 = 0.2242 ⇒ 弱 6.1 倍
```

更致命的是**形状**：把常数偏置 b 代进高斯，
`term(b) ≈ raw₀·exp(−b²/0.5)` ⇒ 每步代价 `≈ −0.543·b²`——**二次型，b→0 处梯度为 0**。
翻译：漂 **1.1 deg/s 与漂 5.7 deg/s，这一项几乎一样不在乎**（−0.0005 / −0.0054 每步），
而 20 秒的 5.7 deg/s 已经等于 115° 航向偏转。**这是"欠定价"的严格含义：价格随偏差平方增长 ⇒ 小偏差免费。**

### (b) 转弯：定价被稀释 3 倍 + 从当前步态盆地不可达

* **稀释（可修的部分）**：完美跟踪指令让 raw 从 0.1415 → 0.2826（+0.282/步 = 4.33%）。
  但上限只有 0.28，是因为**偏航误差与未指令的 ω_x/ω_y 共用同一个指数**（稀释因子实测 0.335）。
  把这一项换成只含 z 的高斯（ω_x/ω_y 已由 `body_ang_vel` 以 −0.05 定价，实测 −0.058/步，属**重复计价**），
  同一条轨迹上 raw = **0.479**（走直）/ **0.403**（+0.6），天花板回到 1.0：
  转弯通道的价格立刻从 +0.282/步 涨到 **+1.194/步（18.3%）= 4.2×**。
* **不可达（真正的墙）**：±0.6 rad/s（±34.4 deg/s）指令，实测净偏航率只动 **+3.45 / −7.19 deg/s**
  （同 32 env 协议；且正负不对称 2.1×）。同协议下 `align_official.onnx`
  ——**我们自己用逐字官方配方重训 9000 迭代的臂**——更差：常驻 −20.35 deg/s 的绕圈，
  指令增益只有 4.7%（+0.6 → −21.54，−0.6 → −24.78 deg/s）。
  而 `|ω_z|` 在**所有**工况恒为 0.87–0.94 rad/s ⇒ 躯干偏航率几乎完全由踏步极限环决定，与指令无关。
  这正是 `mdp.py:6198-6207` 自己写下的结论：*"the turn channel is not under-priced, it is
  **UNREACHABLE from the gait basin** … a forward shuffle whose foot placement is decoupled from the yaw command."*
* **一个额外的可复现证据**：转弯指令下"让出的奖励"只有 4.3–5.8%，而走直时"偏航率振荡"本身值 **4.75%**
  （那一项自己就付 0.32/步）。⇒ **"让躯干少摆一点"比"真的转弯"更容易在同一项里拿分**，
  因为两者进的是同一个高斯。这就是"通道不可达"在奖励账面上的样子。

### (c) 「在观测不到的状态上定价」（任务书第 4 问）

**证据（file:line）**
* actor 观测 **61 维** = `base_ang_vel(3) + projected_gravity(3) + joint_pos(14) + joint_vel(14)
  + actions(14) + command(3) + head_command(4) + body_command(6)`
  ——**没有航向角、没有机体线速度**（`logs/queue_align/align_fwd_export.log:138-150`；
  线速度是被 `[cfg:1598]` 显式删掉的）。
* critic **76 维**同样**没有航向**（同文件 `:153-170`，只多了 `base_lin_vel` + `foot_*` 共 15 维）。
* actor 是**纯前馈 MLP**：61→512→256→128→14，无循环、无历史帧
  （`logs/queue_align/align_fwd_export.log:246-259`；`[cfg:2387] hidden_dims=(512,256,128)`）。

**这意味着什么——correctability 与 learnability 必须分开：**
* **可纠正性（correctability）成立**：角度项是形状上唯一正确的项。速率项只能说"别再转了"，
  角度项才能"奖励把已经漂掉的转回来"（`[cfg:397-398]` 的原话）。这一点在**行为设计**层面没错。
* **可学习性（learnability）不成立**：对**记忆无关**的策略，航向角不是它信息的函数。
  同一个 61 维向量既可能对应 `err=+120°` 也可能对应 `err=−120°`，而
  `d(hold)/d(err) = −2·err/σ²·exp(−err²/σ²)` 在这两点**符号相反** ⇒ 在策略的信息集上取条件期望，
  梯度 ≈ 0，剩下的只是**方差**（噪声）。critic 也看不到航向 ⇒ 连优势函数都无法表示这条依赖，
  于是这个 reward 分量变成 advantage 里一份**不可约的噪声**，而不是可用的梯度。
* **可学的是什么**：策略唯一看得见的偏航量是 `base_ang_vel[:,2]`（观测项 #0）。
  所以"ω_z 要等于指令"和"ω_z 要接近 0"学得到；"航向回到 spawn 朝向"学不到。
* 数值佐证：`heading_hold` 在实测工作点上确实还有可观的值（+0.887/步 = 13.1% 份额），但它的值
  **89.6% 来自 `|err|<30°` 的采样**（`|err|>30°` 占 52.7% 的样本却只贡献 10.4% 的值），
  也就是"第一次漂出去之前"白拿的部分；而 `|err|>90°` 的 22.2% 采样里梯度是 4.8e-4 ≈ 0。
  ⇒ **它付钱给"还没漂"的状态，不付钱给"已经漂了"的状态**——而后者才是要被修正的。

## 建议的唯一改动 + 预期梯度算式

### 改什么

**打开 `MICRODUCK_YAW_DC=1`**。等价于把已经写好的项挂上（不需要写新代码、不改任何别项）：

```python
cfg.rewards["yaw_dc"] = RewardTermCfg(
    func=microduck_mdp.yaw_dc_rate_penalty,
    weight=3.0,                      # 课程 yaw_dc_weight 在 300 迭代内线性爬到 3.0
    params={"command_name": "twist",
            "wz_command_threshold": 0.15,   # 只对直线指令收费，转弯命令永不收费
            "command_threshold": 0.05,      # 站立交给 yaw_hold_zero_cmd
            "tau_s": 0.8},                  # ≈ 两个步态周期
)
```
出处：常量 `[cfg:494-499]`、注册 `[cfg:1141-1150]`、课程 `[cfg:2343-2352]`、
实现 `[mdp:5237-5304]`、默认关 `[cfg:494-495]`。它**不动官方 16 项**，
`tests/test_official_alignment.py` 的逐项等价不会被破坏。

**为什么是它而不是 `heading_hold`**：`yaw_dc` 作用在 `ω_z` 上，而 `ω_z` **在 61 维观测里**
（`base_ang_vel`），actor 与 critic 都看得见 ⇒ 学得到；`heading_hold` 作用在航向上，
两个网络都看不见、且网络无记忆 ⇒ 学不到（见 (c)）。而且它是**因果、稠密、每步**的信号，
不是"结果"。

### 预期梯度算式（全部落在实测工作点上，`α = dt/τ = 0.02/0.8 = 0.025`）

```
yaw_dc(b) = −3.0·|EMA_τ(ω_z + b)|·1[|cmd_z|≤0.15]·1[‖cmd_xy‖>0.05]
          = −3.0·|b|            （b 为持续偏置；‖·‖ 是整流，摆动只经由 EMA 泄漏进入）
TAV(b)    =  2.0·exp(−(b²+ω_xy²)/0.5)  ⇒  Δ ≈ 2.0·0.2716·(exp(−b²/0.5)−1) ≈ −0.543·b²
```

| 量 | 现值（`track_angular_velocity`） | 加 `yaw_dc` 后 | 倍数 |
|---|---|---|---|
| 每步价格 vs 持续偏置 b | `−0.543·b²`（**二次**） | `−3.0·\|b\|`（**线性**） | 形状改变 |
| b = 实测每-env 偏置 **0.1001 rad/s** | `−0.0054/步`（0.080% 总奖励） | **`−0.300/步`（4.45%）** | **55.6×** |
| 边际斜率 `∂/∂b` @ b=0.1001 | `−0.543×2×0.1001 = −0.109 /(rad/s)` | **`−3.0 /(rad/s)`** | **27.6×** |
| vs TAV 轨迹带符号均值 | −0.0518 /(rad/s) | −3.0 /(rad/s) | **57.9×** |
| vs TAV 的 `\|∂\|` 均值 | 0.340 /(rad/s) | 3.0 /(rad/s) | 8.8× |
| 单步（EMA 一步）灵敏度 | — | `3.0·α = 0.075` /(rad/s) | 1.4×（且**不抵消**） |
| 工作点总收费 | +0.3205/步（付给策略） | −0.4552/步（`=3.0×\|EMA\|`，`\|EMA\|=0.1517`）| 总奖励的 **−6.74%** |
| 消除偏置能赚回（b: 0.1001 → 0.0035 rad/s ≈ 官方 0.2 deg/s） | +0.0077/步 = **0.11%** | **+0.290/步 = 总奖励 4.3%** | **37.7×** |
| 对转弯指令的代价 | — | **0（门控）** | — |

**为什么这不是 FACTS §7 里已被证伪的那条"yaw 率惩罚"**（`e6b4003`、rollers 环境原话
"a yaw-RATE penalty froze the yaw and made drift WORSE"）：那条是**裸 `|ω_z|`**，而实测
`|ω_z|` 幅度 0.873 rad/s 是每-env 偏置 0.1001 rad/s 的 **8.7 倍** ⇒ 裸罚把 8.7 倍于信号的
步态摆动一起罚掉（既禁止修正也禁止转身）。`EMA₀.₈` 对 2.3 Hz 步频的衰减是
`1/√(1+(2π·2.3·0.8)²) = 1/11.6 = 8.6%` ⇒ 泄漏从 0.873 降到 **0.052 rad/s**，
**信号:税 从 0.11:1 变成 1.9:1（16.5× 改善）**。另外 `|·|` 是整流 ⇒ 这个 L1 的梯度
**不会**像高斯那样在 `b→0` 处消失——正好补上 (a) 里那个二次型的病。

### 代价、风险与可证伪的预测

* **泄漏税（必须如实记账）**：实测 `|EMA| = 0.1517` 里每-env 偏置占 0.1001、
  **泄漏占 0.052 rad/s ⇒ `3.0×0.052 = 0.156/步 = 2.3% 总奖励`是对步态自身偏航摆动的税**。
  这方向本身是对的（官方 step-locked AC **0.66 deg/s**、`[cfg:474]`；我们 align_fwd **2.816 deg/s**、
  `[walk:269]`，本来就该压 4.3×），但不能把它当成"免费"。
  若训练后偏置降而税不降，把 `YAW_SYMMETRY_TAU_S` 从 0.8 提到 **1.6**
  （泄漏再降一半到 0.026 rad/s，信号:税 3.9:1），代价是 EMA 收敛 2.4 s → 4.8 s（20 s episode 的 24%）。
* **它完全不修转弯通道**（门控关掉了）。按 (b)，转弯要么动课程（`MICRODUCK_TURN_FIRST`，
  已排队 `ours_turn`，`[cfg:519-522]`），要么把 ω_x/ω_y 从 `track_angular_velocity` 的高斯里拆出去
  （4.2× 的价格提升，但那是**偏离官方**的一步，应先做成 env 开关 + 对齐测试豁免）。
* **可证伪的预测**：打开后等 300 迭代爬坡结束、再跑 ~1000 迭代：
  - 若 `|EMA|` 仍停在 0.10–0.15 rad/s ⇒ **"定价不足"被证伪**，剩下的是可达性（步态结构），
    此时再加权重是浪费，应转到步态/落脚结构；
  - 若 `|EMA|` 掉到 0.02–0.05 rad/s（1–3 deg/s）且路径效率跟着涨 ⇒ 这条通道就是主因。
  - **判据一律用 P64**（`eval_straightness.py --num-envs 64`）；AGENTS.md：单环境绝对值可差 20–44× 且翻符号。
